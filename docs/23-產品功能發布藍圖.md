> **設計依據**|docs/19 兩層解耦出貨(先出可用 ERP,彈性與 AI 漸進)+ docs/18 計算層落地序 + docs/17 AI 落地序 + docs/04 完整功能。

## 0. 為什麼分階段(給客戶的說明)

完整的 ERP + MES + ISO + 表單引擎是龐大系統,無法一次到位。分階段交付的原則:

- **每個階段都是「可用的完整成果」,不是半成品** —— R1 就能取代舊系統跑核心營運,不必等全部做完。
- **先解主要痛,再補差異化** —— 客戶最大的痛是「多套系統反覆切換」,R1 先用一個平台整合取代;自助彈性與 AI 是加分,漸進補上。
- **資料不重來** —— 各階段建立的資料與設定沿用到後續階段,升級無縫,不需重建。
- **越用越強** —— 每階段在同一平台上疊加能力,客戶投資持續增值。
- **不必空窗等待** —— 既有 pipeline 客戶近期營運由既有產品支撐;Weyver 為 next-gen 升級路徑,R1 完整範圍前另有 pilot subset 先行(見 §1.5)。

## 1. 四階段功能藍圖

### 🟢 R1 · 一站式上線(首發)—— 用一個平台跑完核心營運

**定位**|取代散落的舊 ERP + Excel + 表單,核心營運當天可用。
**開發時程**|累計約 **2 – 2.5 年**(solo 務實規劃目標;加速 ~1.5 年;R1 完整範圍前有 pilot subset 先行,見 §1.5)。

| 領域 | R1 可用功能 |
|---|---|
| **財會核心** | 總帳 GL · 應收 AR · 應付 AP · 傳票 · 期末結轉 · 試算表 · 台灣電子發票 |
| **進銷存** | 採購單 · 銷貨單 · 訂單 · 庫存進出 · 客戶 / 供應商 / 商品主檔 |
| **生產基礎** | BOM 物料表 · 工單追蹤 |
| **MES 現場** | 平板掃碼 · 工單回報(現場執行 UI)|
| **品保** | 品質檢驗記錄 · 不合格 NCR |
| **ISO** | 文件管制(版本 / 生效 / 審核)|
| **HR 基礎** | 員工主檔 · 打卡 · 排班 |
| **平台** | 統一登入 · 跨模組資料自動流動(採購→財會、NCR→凍結庫存)· ERP 各表可加自訂欄位 · LINE / Email 通知 · 基礎 AI 公式助手 |

**客戶價值**|**一個平台、單一登入,取代分散系統,核心營運日常全流程可跑。**

---

### 🔵 R2 · 完整 ERP + 現場深化 —— 功能對標主流 ERP/MES/ISO

**定位**|R1 之上補齊完整 ERP 深度 + 現場整合。
**開發時程**|累計約 **3.5 年**(solo 務實規劃目標;加速 ~2 年,見 §1.5)。

| 領域 | R2 新增 |
|---|---|
| **財會進階** | 多幣別 + 匯兌損益 · 固定資產折舊 · 銀行對帳 · 成本會計(標準 / 分批)· 庫存估值(加權 / FIFO)· 合併報表 |
| **生產進階** | MRP 需求規劃 · 領退料 · 完整工單 · 工時記錄 |
| **進銷進階** | 儲位管理 · 序號 / 條碼 · 撥料 · 進出口報關 |
| **MES 深化** | Edge Gateway 對接機台(SCADA / 感測器)· OEE 效率 · Andon 異常通報 · 排程比對 |
| **ISO 完整** | 內外部稽核 · CAPA · 客訴 · 供應商評鑑 · 管理審查 |
| **HR 完整** | 薪資計算 · 勞健保 / 二代健保 · 電子薪資單 |
| **平台** | 進階報表 / BI 儀表板 · 全通路通知(Slack / Teams / Telegram / WhatsApp / Discord)|

**客戶價值**|**ERP + MES + ISO 功能對標主流 vendor,深度營運全覆蓋。**

---

### 🟣 R3 · 自助彈性 + AI 加速 —— 你自己配置的平台

**定位**|開放完整表單引擎(Ragic 級彈性)+ AI,客戶自主掌控。
**開發時程**|累計約 **4 – 4.5 年**(完整 MVP 到達,solo 務實規劃目標;加速 ~3 年,見 §1.5)。

| 領域 | R3 新增 |
|---|---|
| **完整表單引擎** | 拖拉自建任意表單 · Excel-like 格編輯 · 自訂公式 · 關聯 Link&Load · 7 種視圖(表格 / 看板 / 日曆 / 圖表 / 表單…)|
| **產業合規自建** | 客戶自建 HACCP / 過敏原 / 蟲害 / 清潔紀錄等產業別表單與流程 |
| **AI 遷移助手** ⭐ | **貼上舊 ERP 畫面 / 上傳 Excel → AI 自動生成等價表單**(導入從數週手工壓縮到數小時 + 人審)|
| **AI 查詢 / 抽單** | 自然語言查詢與報表 · 發票 / 送貨單拍照 → AI 抽取自動建單 |
| **規則引擎** | 客戶**視覺化自訂**稅務 / 定價 / 折扣 / 核准規則(不需寫程式)|
| **行動 / 簽核** | 完整行動 App + PWA · 電子簽章 |

**客戶價值**|**完整 Ragic 級自助彈性 + AI —— 真正「依貴公司流程自由配置」的平台。**

---

### 🟠 R4 · 進階對標 + 智慧營運

**定位**|對標國際 Tier-1 進階功能 + AI-native 智慧。
**開發時程**|**持續演進**(完整 MVP 之後,依客戶付費需求排序,無單一終點,見 §1.5)。

| 領域 | R4 新增 |
|---|---|
| **財會對標** | Multi-book(平行 GAAP / IFRS)· Revenue Recognition · 分步成本 |
| **生產對標** | 完整 MRP II(產能 / 途程)· 進階 WMS |
| **品質對標** | SPC 統計製程管制 |
| **HR 對標** | 招募 · 才能管理 · 教育訓練 |
| **CRM** | 銷售管線 · 商機 · 報價 |
| **AI 智慧** | AI Copilot 對話式操作 · 智慧對帳 · 需求預測 · 異常偵測 / 預警 |
| **企業** | 多廠區 · 集團合併 · 訂閱計費 |

**客戶價值**|**企業級對標 + AI-native 智慧營運。**

## 1.5 各階段開發時程(規劃目標)

| 階段 | 本階段工作量 | **累計時程*(solo 務實)** | 客戶可用里程碑 |
|---|---|---|---|
| 🟢 **R1** 一站式上線 | ~180 人月 | **~2 – 2.5 年** | 核心營運全流程可上線運轉,取代舊系統 |
| 🔵 **R2** 完整 ERP+現場 | +~150 人月 | **~3.5 年** | ERP / MES / ISO 深度對標主流 vendor |
| 🟣 **R3** 自助彈性+AI | +~110 人月 | **~4 – 4.5 年** | 完整表單引擎 + AI(**完整 MVP 到達**)|
| 🟠 **R4** 對標+智慧 | +~390 人月 | **持續演進** | 依付費需求排序,邊做邊上,無單一終點 |

> **\* 時程假設**|以**單一資深開發者(AI 輔助)全職投入**估算之**規劃目標,非交付承諾**;累計時程採**務實檔**(維運部分卸載、Vernova 實測峰值 ×0.3)為對外承諾底線,實證校準見內部 docs/07 §1.4。以交付**順序**為準。**若 pilot 後擴編團隊,R2 之後各階段可再加速。**

**⚡ 務實 vs 加速兩檔(均為單一開發者 AI 輔助之 solo 情境)**|

上表**累計時程**採**務實檔**(對外承諾底線)。以**集中、高強度之 AI 輔助開發**並將既有客戶維運卸載 / 自動化,時程可再壓縮至**加速檔**(內部努力目標):

| 里程碑 | 務實(承諾底線)| 加速(努力目標)* |
|---|---|---|
| R1 一站式上線 | ~2 – 2.5 年 | **~1.5 年** |
| R2 完整 ERP+現場 | ~3.5 年 | **~2 年** |
| 完整 MVP(至 R3)| ~4 – 4.5 年 | **~3 年** |

> **\*** 加速檔為**內部評估之努力目標,非交付承諾**。兩檔差距之關鍵|前期導入密集期收斂(約 2026 下半 ~6 個月)後,既有客戶維運負擔能否卸載至研發專注度維持高檔(加速 ~90% vs 務實 ~80%)。時程主要受**研發專注度之延續性**(而非 coding 速度)與 ERP 財務正確性之驗證負擔影響 —— solo 純 coding 產能經實測(docs/07 §1.4)不是瓶頸。實際交付以每階段之驗收里程碑為依據。

**⏩ 早期成果(不必等 R1 完整範圍)**|

- **首個 pilot subset 先行**|R1 完整範圍前,先交付首客 pilot 可用之核心流程 —— **進料 → 生產 → 出貨 → 開立電子發票 → 批號追溯**,讓客戶提早在真實營運中驗證,再逐步補齊 R1 全部範圍。
- **既有客戶無空窗**|既有 pipeline 產品(2026 下半年分批上線)支撐近期營運;Weyver 為其 next-gen 升級路徑,客戶不需停等新平台完成。
- **每階段皆可收費運轉**|R1 起即為可獨立產生營運價值的完整成果,後續 R2–R4 於同一平台疊加,非「等全部做完才能用」。

## 3. 既有 pipeline 客戶的升級路徑

- **現況**|17 家 pipeline 客戶正導入既有產品。Weyver 為 next-gen 重寫,已上線客戶未來平滑升級。
- **升級原則**|資料與設定遷移,不重建;既有流程在 Weyver 平台上延續 + 疊加新能力。
- **優先順序**|pilot 首客(食品 / 團膳)先上 R1 驗證,再依業務節奏擴散。

---

## 4. 交付承諾原則(對客戶)

1. **每階段皆可用**|不交付半殘功能;每個 R 都能獨立產生營運價值。
2. **先痛點後差異化**|R1 先解「多系統切換」主痛,自助與 AI 漸進。
3. **資料不重來**|各階段資料 / 設定沿用,升級無縫。
4. **一個平台**|所有功能在同一平台、同一登入、同一視覺,不是拼裝多系統。
