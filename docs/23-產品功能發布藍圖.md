> **文件性質**|**對客戶**的功能發布時程,說明各階段可使用的功能範圍。與內部開發文件(docs/13 開發順序、docs/07 R&D 時程)分開 —— 本藍圖為客戶溝通用,以「客戶能用到什麼」為主。

## 0. 為什麼分階段(給客戶的說明)

完整的 ERP + MES + ISO + 表單引擎是龐大系統,無法一次到位。分階段交付的原則:

- **從既有 Ragic 用法無痛遷移起步** —— 客戶目前都在用 Ragic,**R1 先交付完整 Ragic 平台**,現有表單 app 原封搬上 Weyver,零功能損失、零學習成本。
- **先 land 再 expand,差異化隨後補上** —— R1 把客戶遷移上平台(land);R2 讓「**算**」(GL / 成本 / MRP)也不用寫程式,那才是取代 ERP 的付費升級;MES / ISO 於 R3 疊加。
- **資料不重來** —— 各階段建立的資料與設定沿用到後續階段,升級無縫,不需重建。
- **越用越強** —— 每階段在同一平台上疊加能力(同一表單引擎 substrate),客戶投資持續增值。
- **不必空窗等待** —— 既有 pipeline 客戶近期營運由既有產品支撐;R1 完整範圍前可先逐個遷移最常用的 Ragic 表單驗證(見 §1.5)。

## 1. 四階段功能藍圖

### 🟢 R1 · 完整 Ragic 平台(首發)—— 既有客戶無痛遷移上線

**定位**|**既有 Ragic 客戶原封不動遷移上 Weyver**,零功能損失 + 現代平台。表單引擎為 substrate,先做穩地基。
**開發時程**|累計約 **2 – 2.5 年**(solo 務實規劃目標;加速 ~1.5 年;pilot subset 先行,見 §1.5)。

| 領域 | R1 可用功能(Ragic A–I 全套)|
|---|---|
| **表單引擎** | 拖拉自建任意表單 · Excel-like 格編輯 · 子表 · 動態欄位 · **用既有 Excel 建表(onboarding 神器)** |
| **公式 / 自動化** | 自訂公式 · 單據流編排 · 排程 / 觸發 · 通知規則 |
| **關聯** | Link & Load · Lookup / Rollup 跨表帶值 |
| **視圖** | 7 種視圖(表格 / 看板 / 日曆 / 圖表 / 甘特 / 表單 / 地圖)|
| **權限 / 報表** | 三層權限(表 / 欄 / 列)· 報表 BI · 樞紐 · 儀表板 |
| **整合 / UX** | 匯入匯出 · Public Form · REST API + webhook · 基本簽名欄位(合規簽章 TWCA → R2)· 稽核 log · 主題 |
| **平台** | 統一登入 · 多租戶 · 白牌自訂網域 · LINE / Email 通知 · 平台可靠性(冪等 / 斷路 / 配額)|
| **AI / 規則(v6.1 前移 R1)** | **AI 遷移建表助手**(貼舊 ERP 畫面 / Excel → 生成表單)· 基礎 AI 公式助手 · NL 查詢 · No-code 規則編輯器(ZEN 決策表)|

**客戶價值**|**既有 Ragic 用戶當天可把現有表單 app 全部搬上 Weyver,一模一樣還更快 —— land 上平台,後續模組直接疊加。**

---

### 🔵 R2 · ERP 核心 + 計算層 —— 補上「算」的牆,真正取代 ERP

**定位**|R1 之上補齊「**算**」(GL / 成本 / MRP / 估值),而且**維持不用寫程式** —— 這才是客戶付費升級的理由。
**開發時程**|累計約 **4 年**(solo 務實規劃目標;加速 ~2.5–2.7 年,見 §1.5)。

| 領域 | R2 新增(ERP J–Q + 計算層 + HR）|
|---|---|
| **財會核心** | 總帳 GL · 應收 AR · 應付 AP · 傳票 · **期末結轉** · 試算表 · 台灣電子發票 |
| **計算層** ⭐ | GL 過帳期結財報 · AP/AR 沖帳帳齡 · **庫存估值 FIFO / 加權 / 移動** · FX 匯兌 · **標準成本 + 差異 + BOM 結轉** · 折舊 · **MRP 低階碼淨需求** |
| **進銷存** | 採購 · 銷貨 · 訂單 · 庫存進出 · 主檔 · 儲位 · 序號 / 條碼 · 進出口報關 |
| **生產** | BOM · 工單 · 領退料 · 工時 |
| **多 ERP 對帳** | **Q bridge**|客戶既有 ERP(鼎新 / 正航 / SAP B1)onboarding 一次性匯入 / 對帳 |
| **HR 完整** | 薪資計算 · 勞健保 / 二代健保 · 電子薪資單 · 班別加班 |

**客戶價值**|**GL / 成本 / MRP 補上且不必寫程式 → 100% 取代原 ERP,不再需要第二套系統。**

---

### 🟣 R3 · MES 現場 + ISO 品保 —— 一體 offering 完成(完整 MVP)

**定位**|把現場執行與品質管理納入同一平台,ERP + MES + ISO 一體到位。
**開發時程**|累計約 **4 – 4.5 年**(完整 MVP 到達,solo 務實規劃目標;加速 ~3 年,見 §1.5)。

| 領域 | R3 新增 |
|---|---|
| **MES 現場** | 平板掃碼 · 工單回報(現場執行 UI)· **Edge Gateway 對接機台(SCADA / 感測器)** · OEE 效率 · Andon 異常通報 · 排程比對 |
| **品保** | 品質檢驗記錄(IQC / IPQC / OQC)· 不合格 NCR |
| **ISO 完整** | 文件管制 · 內外部稽核 · CAPA · 客訴 · 供應商評鑑 · 管理審查 |
| **產業合規自建** | 客戶於 R1 表單引擎自建 HACCP / 過敏原 / 蟲害 / 清潔紀錄等產業別表單與流程 |

**客戶價值**|**現場 + 品保一體,ERP + MES + ISO 全在同一平台、同一登入(完整 MVP 到達)。**

---

### 🟠 R4 · 對標 + AI 智慧營運 —— 持續演進

**定位**|對標國際 Tier-1 進階功能 + AI-native 智慧。
**開發時程**|**持續演進**(完整 MVP 之後,依客戶付費需求排序,無單一終點,見 §1.5)。

| 領域 | R4 新增 |
|---|---|
| **財會對標** | Multi-book(平行 GAAP / IFRS)· Revenue Recognition · 分步成本 |
| **生產 / 品質對標** | 完整 MRP II(產能 / 途程)· 進階 WMS · SPC 統計製程管制 |
| **HR / CRM** | 招募 · 才能管理 · 教育訓練 · CRM 銷售管線 / 商機 / 報價 |
| **AI 智慧** ⭐ | AI Copilot(對話式操作)· 智慧對帳 · 需求預測 · 異常偵測(v6.1|遷移助手 / NL 查詢 / 規則引擎已前移 R1;拍照抽單前移 R2)|

**客戶價值**|**企業級對標 + AI-native 智慧營運。**

## 1.5 各階段開發時程(規劃目標)

| 階段 | 本階段工作量 | **累計時程*(solo 務實)** | 客戶可用里程碑 |
|---|---|---|---|
| 🟢 **R1** 完整 Ragic 平台 | ~240 人月(v6.4)| **~2 – 2.5 年** | 既有 Ragic 客戶無痛遷移上平台,零功能損失 + AI 建表 / 規則編輯器 + 完整設定中心(用戶管理 / 通知通道 / AI·API 金鑰)|
| 🔵 **R2** ERP + 計算層 | +~223 人月(v6.5)| **~4 年** | 補「算」的牆(GL / 成本 / MRP / 估值)+ ERP-parity(委外 / 票據 / 信用 / 營業稅 / SoD / 連接器)→ 取代 ERP |
| 🟣 **R3** MES + ISO | +~40 人月(v6.1)| **~4 – 4.5 年** | 現場 + 品保一體(**完整 MVP 到達**)|
| 🟠 **R4** 對標 + AI | +~390 人月 | **持續演進** | 依付費需求排序,邊做邊上,無單一終點 |

> **\* 時程假設**|以**單一資深開發者(AI 輔助)全職投入**估算之**規劃目標,非交付承諾**;累計時程採**務實檔**(維運部分卸載、Vernova 實測峰值 ×0.3)為對外承諾底線,實證校準見內部 docs/07 §1.4。以交付**順序**為準。**若 pilot 後擴編團隊,R2 之後各階段可再加速。**

**⚡ 務實 vs 加速兩檔(均為單一開發者 AI 輔助之 solo 情境)**|

上表**累計時程**採**務實檔**(對外承諾底線)。以**集中、高強度之 AI 輔助開發**並將既有客戶維運卸載 / 自動化,時程可再壓縮至**加速檔**(內部努力目標):

| 里程碑 | 務實(承諾底線)| 加速(努力目標)* |
|---|---|---|
| R1 完整 Ragic 平台 | ~2 – 2.5 年 | **~1.5 年** |
| R2 ERP + 計算層 | ~4 年 | **~2.5 – 2.7 年** |
| 完整 MVP(至 R3)| ~4 – 4.5 年 | **~3 年** |

> **\*** 加速檔為**內部評估之努力目標,非交付承諾**。兩檔差距之關鍵|前期導入密集期收斂(約 2026 下半 ~6 個月)後,既有客戶維運負擔能否卸載至研發專注度維持高檔(加速 ~90% vs 務實 ~80%)。時程主要受**研發專注度之延續性**(而非 coding 速度)與 ERP 財務正確性之驗證負擔影響 —— solo 純 coding 產能經實測(docs/07 §1.4)不是瓶頸。實際交付以每階段之驗收里程碑為依據。

## 1.6 開發啟動狀態(2026-07-19 起)

**Phase 1(R1)工程已於 2026-07-19 啟動**,且 R1 關鍵路徑上的**最大技術風險已解除**:

| 項目 | 狀態 |
|---|---|
| **表單引擎核心(平台 substrate)** | ✅ **已交付**(2026-07-19)|自建任意表單 → 系統即時生成真實資料表 · 15 種欄位型別(文字 / 金額 / 日期 / 選項 / 自動編號…)· 子表(單據表頭 + 明細單一交易)· 記錄填寫 / 查詢 / 篩選 · REST API |
| **多租戶隔離** | ✅ **已驗證**|資料庫層級列級防護(RLS)+ 應用層雙防線;含「應用程式漏寫過濾條件仍不洩漏」之對抗性測試 |
| **可擴充性驗證** | ✅ **已壓測**|10,000 張使用者自建表之壓力測試近線性無退化(pilot 規模之 5 倍餘裕)|
| 表單設計器 UI / Excel 建表 / 視圖 / 公式 / 三層權限 | 🏗 依序開發中(R1 範圍)|

此為 R1 排程之**信心依據**:表單引擎的動態資料模型是整個平台最難、風險最高的地基(所有後續模組建構其上),已於工程啟動首日完成設計驗證與核心交付,並經自動化測試(含真實資料庫)全數通過。**§1.5 時程承諾不因此變更**;後續里程碑依序推進。

**⏩ 早期成果(不必等 R1 完整範圍)**|

- **首個 pilot subset 先行**|R1 完整範圍前,既有客戶可先把最常用的 Ragic 表單 app(進銷存 / 採購 / 訂單 / 主檔 / 品質)**逐個遷移上 Weyver** 驗證,再補齊 A–I 全部功能。電子發票 / 批號 / GL 等 ERP 流程於 **R2** 補上。
- **既有客戶無空窗**|既有 pipeline 產品(2026 下半年分批上線)支撐近期營運;R1 讓客戶把現有 Ragic 用法**原封搬上新平台**,不需停等後續 ERP/MES/ISO 完成。
- **每階段皆可收費運轉**|R1 為既有客戶遷移 land(平台年費);R2 補「算」為付費升級(ERP 增量);後續 R3–R4 於同一平台疊加,非「等全部做完才能用」。

## 3. 既有 pipeline 客戶的升級路徑

- **現況**|17 家 pipeline 客戶正導入既有產品。Weyver 為 next-gen 重寫,已上線客戶未來平滑升級。
- **升級原則**|資料與設定遷移,不重建;既有流程在 Weyver 平台上延續 + 疊加新能力。
- **優先順序**|pilot 首客(食品 / 團膳)先上 R1 驗證,再依業務節奏擴散。

---

## 4. 交付承諾原則(對客戶)

1. **每階段皆可用**|不交付半殘功能;每個 R 都能獨立產生營運價值。
2. **先痛點後差異化**|R1 先解「多系統切換」主痛,自助與 AI 漸進。
3. **資料不重來**|各階段資料 / 設定沿用,升級無縫。
4. **一個平台**|所有功能在同一平台、同一登入、同一視覺,不是拼裝多系統。
