品牌故事

三家 ERP 是線頭,Weyver 織成一朵雲

客戶散落的三套 ERP、五份 Excel、十個 Ragic 表單 —— 都是線頭;
Weyver(織雲)是把它們織成一整朵雲的織者。

中文品牌

網域

weyver.io、weyver.app 可註冊

首個客戶樣態

鮮勇|食品加工 · 既有 Ragic 用戶 · 內部有 3 家 ERP

現況痛點

  • 3 家 ERP 各記各的,對帳靠人工
  • Ragic 表單已用來補 ERP 缺口(基本資料 / 進銷存 / 生產 / IOT)
  • 食品業合規壓力大(批號 / 效期 / HACCP / 電子發票)

Weyver 為何是解

  • Q 模組|多 ERP 對帳直擊「3 家 ERP」問題
  • Ragic-like 表單引擎 + 完整 ERP 領域邏輯 → 不用兩套系統
  • 食品業特化(M 批號 / P 三角貿易 / R HR 班別)

TAM 假設:台灣中小型食品 / 傳產有多家 ERP + 用 Excel 補洞的客戶 → 市場規模需在 docs/05 商業模式驗證階段量化

產品範圍

19 模組|Ragic 9 + ERP 8 + HR + CRM

定位:以 Ragic 功能為基底 + 結合主流 ERP 的多租戶 SaaS

Ragic 側(A–I)

  • A 平台地基 / 多租戶
  • B 表單引擎 / Grid
  • C 公式 / 自動化 / 單據流
  • D 關聯 Link & Load
  • E 三層權限
  • F 報表 / BI / 視圖
  • G 匯入匯出 / API
  • H UX / 通知 / 稽核 / 電子簽章
  • I Ops / 後台

ERP 側(J–Q)

  • J 財會 GL/AP/AR/多幣別
  • K 進銷存 + 序號 + 儲位
  • L 生產 BOM / 工單
  • M 品保 + 批號(食品)
  • N 成本計算
  • O 電子發票合規
  • P 進出口 + 三角貿易
  • Q 多 ERP 對帳(差異化)

HR + CRM(R–S)

  • R HR / 薪資 / 班別(食品廠必需)
  • R 打卡 / 差勤
  • R 勞健保 / 二代健保
  • S CRM 輕量 MVP 不包
S:食品 B2B CRM 需求集中在聯絡人+服務單,由 D 關聯覆蓋。
範圍外|MES + ISO 對接第三方 vendor(工研院 MES / eISO / 客戶既有解),Weyver 不自研。理由:多租戶 SaaS 與 MES 現場硬體(SCADA)天然衝突;ISO 有專門 vendor,非核心差異化。若客戶硬要求 Weyver 自建 → +46 MVP。

技術路線

路線 A(Odoo fork)相比 B(全自研),省 40–47%

路線 A|垂直 SaaS + Odoo fork

323 人月

ERP 財會 / BOM / 庫存 / HR 借 Odoo 驗證過的模組,fork 後改多租戶 + 台灣化。

路線 B|全自研

533–603 人月

從零寫 GL / 期結 / 合規邏輯 / MRP / 薪資勞健保。時程 × 1.8。

ERP + HR 領域邏輯不要自己寫。這是路線 A 最強立論。

縮短見金流時間

Phase 0 140 人月 · 22 個月上線收費

階段範圍人月8 人時程
Phase 0|PoC 收現金 Ragic 90 + J 財會核心 + O 電子發票 + M 批號 + R HR 精簡 140 ~22 月(1.8 年)
Phase 1|完整 MVP 補 K/L/N/P/Q + R 完整 + Ragic 進階(BI / mobile 部分 / 稽核 / Kanban Cal) +181 +28 月(累計 4.2 年)
Phase 2|對標水準 訂閱計費 + CRM + Mobile 完整 + MRP II + 分步成本 +280 (邊收邊做)

不用等 4.2 年見金流。Phase 0 定義的 5 塊,是食品廠客戶能上線的最小可付費組合。MES / ISO 對接第三方。

技術風險

9 個命門子功能|做不好整個產品廢掉

模組子功能為什麼是命門
A動態 schema平台地基,選錯後面難改
BGrid 引擎建議授權 AG Grid Enterprise(省 8–10 人月)
C公式引擎第二護城河,需 compiler / spreadsheet 資深工程師
C單據流編排ERP 靈魂 workflow,沒串好 ERP 感就沒了
JGL 合規 + 多幣別台灣科目表 / 期結 / 匯兌損益錯了合規炸鍋
M批號追蹤食品召回法規要 F/B traceability,做不到不能賣食品業
O電子發票法規強制,做不對客戶開不了發票
Q多 ERP 對帳對外核心承諾,做不好 Ragic 就贏了
R薪資 + 勞健保台灣合規敏感,錯一分錢客戶就開告
最大隱藏風險

人才風險 > 錢的風險

需要台灣市場現況
Grid / 動態 schema / 公式引擎 資深工程師(2–3 名)稀缺,做過 spreadsheet / low-code 平台的更少
Odoo fork + 台灣本地化 資深工程師(1–2 名)稀缺,台灣 Odoo 社群小
ERP 財會領域顧問(兼職)中,顧問公司可外包
食品業 QC / 批號 / HACCP 領域顧問(兼職)中,食品公會 / 顧問公司可找
HR / 薪資 / 勞健保 台灣合規顧問(兼職)中,人事外包公司可外包

找不到 grid / 公式引擎 / Odoo fork 人 = 時程 × 2。這比路線 A/B 差別更嚴重。
