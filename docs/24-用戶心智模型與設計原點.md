## 0. 核心命題

Weyver 既有客戶皆為 **Ragic 使用者**(首客鮮勇亦然),故全體使用者為 **Ragic 範式思考者**。其心智模型為「**建立表單 → 於網格填改資料 → 以 Link & Load 連結 → 以公式計算**」。由此推導三條設計原點:

1. **主要畫面 = Ragic no-code 表單資料庫「自己建、自己填」**之網格/表單(含 sheet/app 列表 + 網格 + 單筆表單 + 表單設計器),**非**唯讀 KPI 儀表板。
2. 儀表板為**主管角色之次要視圖**;以儀表板為主畫面偏離多數使用者心智模型(即「為 SaaS 而 SaaS」)。
3. **整合非並列**|**Ragic 為常駐主體**;ERP / MES / ISO 之功能**織入同一 Ragic 範式**(更進階的表單/表格 + 底層算力/執行/合規),**非各自一個頂層模組 tab**。

> **2026-07-19 客戶端校準(已確認)**|(1)(2)(3) 皆成立。使用者平時**以 Ragic 為主**(自由度高,已可用 Ragic 重建 ERP 大部分功能)。客戶核心痛點 = **不想在多個系統間切換**,故將 Ragic 為主 + 主流 ERP + MES + ISO **整合於同一平台**;**不是每個系統各一個 tab**。若把 ERP/MES/ISO 做成分立模組 tab,等同讓使用者又在切系統,直接違背產品價值主張。

## 1. 四系統的產品定位 + 用戶心智模型

| 系統 | 產品定位 | 使用者每日主要畫面 | 核心物件 → 動作 | 心智模型(腦中概念) |
|---|---|---|---|---|
| **Ragic(基底)** | no-code 表單資料庫;自建自填 | 網格列表 / 單筆表單 / 表單設計器 | 表單 · 記錄 · 子表 · 關聯 → 建、填、改、連、算 | 「我的表單／表格／記錄／關聯」= Excel 高手自建資料庫。**Weyver 全體之母心智模型** |
| **主流 ERP** | 交易與帳務真實來源 + 補「算」的牆(GL/成本/MRP/估值) | 單據錄入 / 待簽核 / 對帳 / 帳表 | 單據(採購/銷貨/傳票)→ 開、送簽、過帳、對帳、期結 | 「單據 → 簽核 → 過帳 → 帳要平 → 期末結」。於 Weyver 仍是 **Ragic 式表單**,底層補算力 |
| **MES 現場** | 將辦公室表單接至實體產線(Edge) | 操作員:工單佇列 / 生產回報;主管:線況總覽 | 工單 · 生產回報 · 批號 → 領工單、掃碼、回報、追溯 | 操作員=「現在做哪張工單、掃碼回報」;工單/回報**亦為引擎上的表單** + Edge 餵資料 |
| **ISO 品管** | 合規與文件控制 | 受控文件庫 / 稽核 / CAPA 流程 | 受控文件 · 版本 · 稽核發現 · 矯正措施 → 建檔、審核、稽核、改善 | 「受控文件/版本/稽核發現/矯正措施」= Ragic 範式的自建表單 + 工作流 |

### 1.1 Ragic(基底) —— 母心智模型

- **定位**|Excel 式雲端資料庫 / no-code 表單為中心(`docs/10 §1.1`)。使用者為「自建資料庫」而非「消費既成 app」。
- **每日現實**|停留於**可編輯網格**填改資料、設計/調整表單、拉 Link & Load、寫公式。**編輯**是常態,非唯讀瀏覽。
- **設計含意**|網格與表單為第一級介面。表單設計器(點欄位 → 右側 property panel)、Link & Load(右側 slide panel 即時預覽)為招牌互動,須勝過 Ragic 2012 代 UI(`ui-design-analysis.md`)。

### 1.2 主流 ERP —— 單據與帳務心智模型

- **定位**|交易系統真實來源 + Ragic 過不去的「算」(`docs/10 §5b.2`:GL / 成本 / MRP / 估值 / 電子發票 / 高頻稽核)。
- **每日現實**|會計/採購**錄入單據 → 送簽核 → 過帳**;期末**對帳與結轉**。關注「借貸是否平、期能否結」。
- **設計含意**|單據錄入須沿用 Ragic 表單手感(header + 子表 line items),**不另造一套錄入 UX**;差別在底層計算層(過帳/沖帳/期結)與其可視化(試算表恆平衡的信任訊號)。**帳務不可變**(過帳後開反向沖轉)須於介面明示。

### 1.3 MES 現場 —— 執行與追溯心智模型

- **定位**|把辦公室表單接到實體產線(Cloud + Edge hybrid,`docs/08`)。
- **每日現實**|**操作員**心智=「我的工單佇列 / 領工單 / 掃碼回報生產」——平板、觸控、大目標、離線可用;**主管**心智=「線在跑嗎 / OEE / 停機」——監控視圖。
- **設計含意**|操作員主畫面 = **工單佇列 + 生產回報表單**(仍是引擎上的表單),非監控儀表板;監控儀表板(OEE / 產線狀態時間軸 / 停機)為**主管次要視圖**。雙密度:現場疏朗觸控 / 辦公密集滑鼠。

### 1.4 ISO 品管 —— 文件控制與合規心智模型

- **定位**|通用品質工具平台;產業特化由客戶 ISO 專員於表單引擎自建(`docs/04`:B+C self-service)。
- **每日現實**|ISO 專員**自建檢驗表/文件/CAPA**、管理受控文件版本、跑稽核、追蹤矯正措施。
- **設計含意**|文件控制、稽核、CAPA 呈現(fishbone / 5-Why / 版本 timeline,`ui-design-analysis.md`)須現代化,但底層仍是「使用者自建的表單 + 工作流」,與 Ragic 範式一致。

## 2. 統一心智模型 —— Ragic 範式

Weyver 的統一心智模型非「四個 SaaS app 各配儀表板」,而是「**一切皆為使用者(或其管理員)自建的表單/表格,互相連結;差別在系統現在能替其完成 Ragic 做不到的『算 / 執行 / 合規』**」。

- **一致性來源**|同一個 **Ragic 範式的操作手感**(建表單 / 填網格 / Link & Load / 公式),**非**同一套視覺 token 的儀表板。
- **整合非並列(關鍵)**|Ragic 為**常駐主體**;ERP / MES / ISO 為**織入**之進階能力(更進階的表單/表格 + 計算/執行/合規層),**非**與 Ragic 並列之頂層模組 tab。導航沿用 **Ragic-native 之表單/應用組織**(使用者自建之結構),**非** ERP 式模組選單。將四者做成分立 tab = 重現「切多系統」,違背核心痛點。
- **一體性**|此即 `ui-design-analysis.md` signature「所有企業管理工作在同一個視覺系統」的**互動層本質**(不只是視覺層):使用者始終在**同一個 Ragic 式工作區**內,ERP/MES/ISO 的能力「就在那裡」,不需切換到別的系統/tab。

## 3. 設計原點(自心智模型推導)

| 原點 | 內容 |
|---|---|
| **主要畫面** | Ragic「自己建、自己填」之網格 + 表單 + sheet/app 列表 + 表單設計器 為第一級;儀表板為次要 |
| **一致性來源** | Ragic 範式操作手感(建/填/連/算),非視覺 token 儀表板 |
| **導航** | **Ragic-native**(使用者自建之表單/應用組織);**非** ERP 式模組選單,**非**「每系統一個 tab」 |
| **整合模型** | Ragic 為常駐主體,ERP/MES/ISO **織入**為進階表單 + 底層算力/執行/合規;**非**四者並列之頂層模組 |
| **角色分面** | 操作員=工單佇列/回報 · 會計=單據錄入/對帳 · ISO 專員=文件/CAPA · 主管=儀表板(次要);皆於同一 Ragic 工作區內 |
| **儀表板定位** | 監控/彙總之次要視圖,非產品入口或主畫面 |
| **視覺** | 色彩/字型/token 為下游(`docs/14`);IBM Plex 鎖定 |

## 4. 反面教材(避免)

- 以**經理 KPI 儀表板為主畫面** —— 偏離多數使用者(操作員/會計/ISO 專員)之每日現實,即「為 SaaS 而 SaaS」。
- 將 ERP / MES / ISO 做成**各自的頂層模組 tab / 分立系統入口** —— 等同讓使用者又在多系統間切換,直接違背「不想切多系統」之核心痛點(`§0`、`§2`)。
- 讓 ERP 單據錄入變成 Ragic 網格之外的**另一套互動範式** —— 應收斂於同一 Ragic 範式。
- 四模組各自不同的操作手感 —— 破壞「一個工作區」的心智一致性。

## 5. 客戶端校準

### 5.1 已確認(2026-07-19,依既有客戶第一手觀察)

1. **「Ragic 範式思考者 + 主要畫面是網格/表單」成立**。
2. 使用者**每日最常停留畫面 = Ragic no-code 表單資料庫「自己建、自己填」**。→ 設計原點定於此。
3. ERP/MES/ISO **為「同一工作區裡的表單」**,非分立系統:使用者平時以 Ragic 為主(自由度高,已可用 Ragic 重建 ERP 大部分功能),核心痛點 = 不想在多系統間切換,故整合於同一平台,**不是每系統一個 tab**。

### 5.2 待續(仍需第一手細節)

- 操作員現場作業(掃碼 / 離線 / 平板)之實際流程細節。
- 各角色(操作員 / 會計 / ISO 專員 / 主管)登入後之預設落地畫面與優先序。
