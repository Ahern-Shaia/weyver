## 1. 目標與範圍

### 1.1 目標

1. **租戶自有網域直達**,網址列**保持**在客戶自己的網域(不是轉址回我方)。
2. **品牌客製自助**:logo / favicon / 橫幅 / 登入頁 / 主題色,**全部不寫 HTML/CSS**。
3. **設定不需要寄信給我方** —— 全部在租戶設定中心自助完成。

### 1.2 為什麼優先於另兩個 H 缺口

`docs/23` R1「平台」列**逐字寫著「白牌自訂網域」**,矩陣亦標 R1 ✅
—— 三個 H 缺口裡**只有它對客戶明文承諾過**(2026-08-05 查證)。

### 1.3 不做的事

| 不做 | 為什麼 |
|---|---|
| **自訂 HTML / CSS 注入** | 這正是 Ragic 踩的坑(§0.3c)。給了它就等於承認「我們的設定不夠用,你自己寫」;而且是 **XSS 與資料外洩的直路**(自訂 CSS 可用 `background-image: url()` 把畫面內容側錄出去)。**要什麼就做成設定項** |
| 每個「頁籤組」各自的 logo / 橫幅 | Ragic 有(§0.3b),但我方 IA 是分類目錄不是頁籤組,概念對不上。**不為了對齊一個我們沒有的概念而發明一個** |
| 自訂寄件網域(SPF/DKIM) | 已在 `H 通知通道連接 UI` 的 scope 內,不重複 |
| 客戶自帶憑證上傳 | on-demand TLS 自動簽發已覆蓋 99% 情況;自帶憑證是企業版議題,列 P1 |
| 行動 App 圖示 / 名稱 | 我方無原生 App |

## 2. 剩餘 scope 切分

| # | 切分 | 說明 | 相依 |
|---|---|---|---|
| **A1 host → 租戶解析** | Guard 能從 host 決定租戶;host 與 session 不一致的處理 | 🔴 **地基,必須先做** |
| **A2 網域自助綁定** | 租戶填網域 → 顯示 CNAME 指引 → 驗證 → Caddy `ask` 放行 → 自動簽發 | 依賴 A1 |
| **A3 品牌客製** | logo / favicon / 橫幅 / 登入頁文案 / 主題色,per-tenant 儲存與套用 | 獨立,可先行 |

## 3. 資料模型(草案)

```
tenants  (既有表加欄,皆 nullable → 零遷移)
  + custom_domain        text UNIQUE     -- 'erp.客戶.com'
  + custom_domain_state  text            -- pending | verifying | active | failed
  + custom_domain_error  text
  + favicon_file_key     text
  + banner_file_key      text
  + theme                text            -- navy | teal | graphite
  + login_headline       text            -- 取代「自訂載入頁面」的 HTML(§1.3)
  + login_subline        text
  + hide_signup          boolean NOT NULL DEFAULT false
  -- logo_file_key 已存在(schema.ts:58)
```

> **為什麼把品牌欄位放 `tenants` 而不是另立表**|它們是**每租戶恰好一組**的純設定值,
> 沒有生命週期也沒有版本。另立表只會多一次 join,而 `tenants` 已經是設定的落點
> (`timezone` / `default_locale` / `default_currency` 都在那裡)。

## 4. 開放問題(OQ-WL-N)— 待裁定

| # | 議題 | 選項 | 建議 |
|---|---|---|---|
| **OQ-WL-1** ⭐⭐ | 自訂網域是**轉址**還是**真的服務** | A. 轉址(Ragic 的做法)<br>B. **真的在該網域上服務** | **B** —— A 等於沒做,§0.3(a) 官方自述就是 A,照抄 A 是 parity 不是向上。**代價誠實**:B 要 on-demand TLS、要 host→租戶解析、要處理 cookie domain 與 CSRF origin,工程量遠大於 `docs/25` 記的 1 人月 |
| **OQ-WL-2** ⭐⭐ | host 與 session 的 active org 不一致怎麼辦 | A. 以 host 為準強制切換<br>B. 以 session 為準忽略 host<br>C. **以 host 為準,但需重新確認身分** | **C** —— A 會讓「換個網址就切租戶」變成一種**橫向移動**;B 會讓客戶在自己的網域上看到別家資料(災難)。既有 `auth-guard.ts:62-79` 的「讀放行 / 寫擋」是同一類問題的既有解,**沿用它的判斷而不是新發明** |
| **OQ-WL-3** ⭐⭐ | 網域驗證怎麼做 | A. 只查 CNAME 指對<br>B. **CNAME + 一次性 TXT 驗證所有權**<br>C. 不驗,誰填誰有 | **B** —— C 是**網域挾持**(填別人的網域讓憑證簽到自己名下);A 不足以證明所有權(CNAME 可能是舊的殘留)。TXT 是業界標準做法 |
| **OQ-WL-4** ⭐ | Caddy `ask` endpoint 的安全 | A. 公開端點<br>B. **內網 + 共享密鑰,且只回 yes/no** | **B** —— 這個端點決定「要不要為這個 host 簽憑證」,公開等於任何人可用我方額度打 Let's Encrypt。**且回應不得洩漏租戶存在與否**(只回 200/403,不回名稱) |
| **OQ-WL-5** ⭐ | 主題選擇存哪一軸 | A. 只租戶<br>B. 只個人<br>C. **租戶預設 + 個人覆寫** | **C** —— 與 `default_locale` / `locale` 完全同構(§0.1),**同一種語意就該同一種做法**。順便修掉「主題重整就掉」那個既有缺陷 |
| **OQ-WL-6** | 登入頁客製的邊界 | A. 開放 HTML/CSS<br>B. **固定版面 + 具名欄位**(標題 / 副標 / logo / 橫幅 / 隱藏註冊) | **B** —— A 是 §0.3(c) 那個坑,且是 XSS 直路。B 涵蓋 Ragic 那五項的**全部意圖**而不需要使用者寫程式 |
| **OQ-WL-7** | 上傳擋錯要不要照抄 Ragic | — | **抄**(尺寸建議 + CMYK 拒收)。§0.3(b) 那個 CMYK 檢查是**踩過坑才會有的細節**,不是裝飾 |

## 5. FMEA(pre-mortem)
