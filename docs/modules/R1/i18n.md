> 「Ragic 目前提供**英文、繁體中文、簡體中文、西班牙語、日語、法文六種語言版本**。
> 需要其他語言的使用者介面,透過翻譯功能讓你能將介面語言翻譯成使用者熟悉的語言……
> 點選左上角的**漢堡選單**,並點擊**帳號設定**下的**介面翻譯**。
> 在**翻譯成語言**中挑選要翻譯的語言;在**介面分類**挑選要翻譯的功能類別。
> **藍字是它所代表的功能,請不要編輯這些藍字。綠字則填寫欲翻譯成的語言**,
> 翻譯完成之後記得按下**儲存**按鈕。翻譯完成後,就可以選擇翻譯的語言,介面就會自動轉換了。」

同源 `doc/56`(公司設定)另有:

> 「**帳號預設語言**:預設使用者登入資料庫的介面語言。」

**從逐字文本推得的四件事**:

1. **內建六語**,不是三語 —— 我方 `docs/25` 寫「中/英/日」**低估了 parity 標的**。
2. 🔴 **真正的形狀是「租戶自己翻」**,而不是「原廠支援幾種語言」。
   這與第一約束同源:**不用等原廠、不用開票、不用寫程式**。
   只出貨三種語言而沒有自助翻譯,是**做了一個看起來像但不是**的東西。
3. **翻譯以「介面分類」分組**,逐 key 呈現「原文(藍,不可編輯)/ 譯文(綠)」→
   訊息目錄必須**有命名空間**,且 key 對使用者可見。
4. **語言有兩軸**:租戶預設 + 使用者個人選擇。與我方既有欄位一致(§0.1)。

**明文未涵蓋(標為未查證,不得寫成「Ragic 沒有」)**:
本文件**沒有**提到使用者自建內容(表單名 / 欄位名 / 選項值)是否可多語。
針對「欄位名稱 + 翻譯 / 多語」對 582 份鏡像做全文掃描,**零命中** ——
**「文件沒寫」≠「沒有」**(AGENTS.md〈向上設計三條〉①)。故本模組
**把使用者資料的多語明確排除在 scope 外**(§1.3),不拿它當差異化宣稱。

## 1. 目標與範圍

### 1.1 目標

1. **介面可切換語言**,租戶預設 + 個人覆寫(既有欄位直接生效)。
2. 🔴 **租戶自助翻譯介面** —— 管理員在設定頁逐條填譯文,存檔即生效,**不寫程式、不開票、不等我方**。
3. **伺服器端訊息一併多語**(錯誤信封、通知內容),否則使用者切了語言仍會看到中文錯誤。

### 1.2 為什麼是這個順序

`docs/23` 對客戶的 R1 承諾**沒有列多語**(2026-08-05 查證),
所以本模組的驅動力是 **Ragic parity + 遷移阻力**,不是既有承諾。
首波客戶(食品加工,台灣)對多語需求低 —— **這是本模組可以排在 B 段深度 parity 之後的理由**,
而不是可以做半套的理由。

### 1.3 不做的事(並說明為什麼)

| 不做 | 為什麼 |
|---|---|
| **使用者自建內容多語**(表單名 / 欄位名 / 選項值) | Ragic 是否有此功能**未查證**(§0.3);且它會污染 metadata catalog 與動態 identifier 白名單 —— 欄位顯示名是修改紀錄與公式的鍵(`record_revision.changes` 以顯示名為鍵),多語化會讓「同一欄」在不同語言下有不同的鍵。**這是地基級的變動,不能塞在 i18n 模組裡** |
| 語言別的網址前綴(`/zh/`、`/en/`) | 我方是登入後的內部系統,不是要被搜尋引擎索引的公開站。`next-intl` 的 `middleware` / `routing` export **刻意不用**,語言取自使用者設定 |
| RTL(阿拉伯 / 希伯來) | 六語內建目標裡沒有 RTL;版面鏡像是另一個量級 |
| 機器翻譯自動填 | 可作為 P1。P0 先讓「人能翻」,自動翻是加速不是能力 |
| 貨幣 / 數字 / 日期在地化 | **已完成**(`useDisplayCtx` + `Intl.*`),不重複做 |

## 3. 資料模型(草案)

```
locale_override (Tier-1,RLS FORCE;app 車道 SELECT / INSERT / UPDATE / DELETE)
  id          bigint PK
  tenant_id   bigint NOT NULL
  locale      text   NOT NULL        -- BCP-47,如 'ja' / 'vi'
  namespace   text   NOT NULL        -- 對應 Ragic 的「介面分類」
  key         text   NOT NULL
  value       text   NOT NULL
  updated_by  bigint
  updated_at  timestamptz NOT NULL
  unique (tenant_id, locale, namespace, key)
```

> **為什麼是逐 key 一列而不是整包 JSONB**|翻譯是**多人逐條、長期漸進**的工作,
> 整包 JSONB 會讓兩個人同時翻不同分類時互相覆蓋(last-write-wins 吃掉對方)。
> 逐列則天然無衝突。代價是列數多(六語 × 5,000 key 上限 30,000 列/租戶),
> 但那是**一次性且可快取**的量。

## 4. 開放問題(OQ-I18N-N)— ✅ 已裁定 2026-08-05:**全採建議**

| # | 議題 | 選項 | 裁定 |
|---|---|---|---|
| **OQ-I18N-1** ⭐⭐ | scope 要不要含「租戶自助翻譯」 | A. 只出貨 N 種語言<br>B. **出貨 N 種 + 租戶自助翻譯** | **B** —— A 是「看起來像但不是」:Ragic 的功能核心就是自助(§0.3 逐字)。且 A 的隱含承諾是「你要的語言請等我方」,直接違反第一約束。⚠️ **選 B 則 2 人月的估算必須重估** |
| **OQ-I18N-2** ⭐ | 內建幾種語言 | A. 中(繁)<br>B. **繁中 + 英**<br>C. 對齊 Ragic 六語 | **B** —— 有了自助翻譯之後,「原廠出幾種」就不再是能力邊界。C 的六語我方無母語者可校對,**出一份錯的翻譯比不出更傷**(客戶會拿它當品質訊號) |
| **OQ-I18N-3** ⭐⭐ | 5,000 條硬寫中文怎麼搬 | A. 手工逐檔改<br>B. **`next-intl` SWC extractor 抽出 + 漸進遷移**<br>C. 執行期以中文原文當 key | **B** —— 套件已附 extractor(§0.2),不用自己寫。C 看似省事,但中文原文當 key 會讓**文案微調變成破壞性變更**(改一個字全語言失效) |
| **OQ-I18N-4** ⭐ | 伺服器端訊息怎麼多語 | A. 後端回譯好的字串<br>B. **後端回錯誤碼 + 參數,前端翻**<br>C. 不翻 | **B** —— 後端不知道「這個請求該用哪個語言」時的預設一定會錯(背景工作 / webhook 尤然);且錯誤碼本來就該是穩定契約。**代價誠實**:`errors.ts` 現有的中文訊息要逐條換成碼 + 參數,那是既有介面的破壞性變更,須一次做完 |
| **OQ-I18N-5** | 租戶覆寫怎麼合進請求 | A. 每請求查 DB<br>B. **快取 + 版本號失效** | **B** —— `getRequestConfig` 是每個請求都跑的熱路徑(§0.2)。以 `(tenant, locale)` 為鍵快取,租戶存檔時 bump 版本 |
| **OQ-I18N-6** | 缺漏 key 顯示什麼 | A. 顯示 `namespace.key`<br>B. **掉回內建語言的字串**<br>C. 空白 | **B** —— 翻到一半的租戶(常態)不該看到滿畫面的 `settings.profile.title`。`getMessageFallback` 現成 |

## 5. FMEA(pre-mortem)

| # | 失效 | 嚴重度 | 緩解 |
|---|---|---|---|
| I1 | 租戶翻譯裡塞 HTML / script → 存進 message 後被渲染 | **P0** | 譯文一律當**純文字**渲染,不走 `dangerouslySetInnerHTML`;存入時長度上限 + 拒控制字元。**LLM/使用者輸入不得成為可執行內容**(AGENTS.md 🔒 3) |
| I2 | 譯文含 ICU 佔位符不符(原文有 `{count}` 譯文沒有)→ 執行期爆炸 | **P0** | 存檔時比對佔位符集合,不符即拒並指出缺哪個 |
| I3 | 租戶 A 的譯文出現在租戶 B | **P0** | `locale_override` 開 RLS FORCE + 快取鍵含 `tenant_id` |
| I4 | 抽字串遷移時漏掉一批 → 部分畫面永遠中文 | P1 | CI 檢查:`apps/web/src` 不得出現裸中文字串(白名單既有未遷移檔,逐批縮小)。**規則要配檢查**(`pitfall-rule-without-check-always-drifts` 第七次) |
| I5 | 錯誤碼化之後,舊前端拿到碼卻顯示不出來 | P1 | 前後端**同一次部署**;過渡期後端同時回 `code` 與 `message` |
