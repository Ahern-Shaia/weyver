### 0.3 巨人三:競品(Ragic 官方逐字,本機鏡像,查證 2026-08-05)

#### (a) 🔴 它的 PDF 是 **Node + Puppeteer** 的獨立服務

**來源**|`.../doc-kb/284/enable-pdf-downloads-on-server-without-internet-access.html`

> 「在**私有主機版**中,**PDF 下載功能自建的需要條件為 node & Puppeteer**
> (此為進階功能,建議由資深系統管理人員進行安裝及維護)。
> 當前支援的版本為:Node(v.14.19.3)以及 Puppeteer(v.14.4.1)……
> 接著在這個位置下 Command 安裝 Puppeteer,指令為:`npm i puppeteer@14.4.1`……
> 接著下 Command:`node web/sims/js/pdfMaker/nodeJs.js 8888`。
> **注意:請不要將 cmd 畫面關掉,它必須一直執行。**……
> 在**私有主機設定**裡修改值為:`PDF_SERVER_URL=http://localhost:8888`。」

**三個可直接用的判讀**:
1. 業界既有玩家在同一個問題上選了 **HTML → headless Chrome → PDF**,不是 PDF DSL。這是實證,不是猜測。
2. 它是**獨立行程 + URL 設定**(`PDF_SERVER_URL`),不是塞在主程式裡 —— 與我方 modular monolith 的「按技術特性抽單元」(`docs/11 §1.3`)同構。
3. 版本被釘在 2022 年的 Node 14 / Puppeteer 14 —— **headless 瀏覽器的升級成本是真的**,設計時要把它隔在一個介面後面。

#### (b) 🔴 「客製列印報表」的範本 = **Word 檔 + 一套參數語言**

**來源**|`.../doc/138/custom-print-report.html`(標題「客製列印報表」)

> 「Ragic 提供客製列印報表功能,可將表單資料匯出為自訂格式檔案,包括 **PDF、DOCX、PNG、XLSX、PPTX** 等。」
> 「首先,系統會先確認你是否已經有一個已經設計好了的檔案(**Word、Excel 或 PowerPoint**)可以上傳當作範本。」
> 「**只有開放系統管理者 SYSAdmin 有建立與設定客製列印報表範本的權限。**」
> 「**欄位參數**可參考上傳範本頁面中的**欄位語法產生器**……點擊該欄位的語法會直接**複製參數**,便可以快速貼到你的範本中。」
> 「**子表格:只需要參考下圖語法,寫 `[i]` 和 `[i+1]` 兩列即可**,並且列 `[i+1]` 中只需加入其中任一欄位的語法,即可代表整列資料。」

實際參數長這樣(官方範例逐字):
`{d.1002578:html}` · `{d.1002581:html(inline)}` · `{c.now:formatD('YYYY-MM-DD HH:mm:ss')}` ·
`:convCRLF` · `IMG:html` · `{o.preReleaseFeatureIn=5002000}`

並附 **10 條「限制與注意事項」**,包含:
> 「當表單的欄位過多導致表單**寬度過大**時,下載的範本會**無法顯示超出範圍的欄位**,請參考欄位語法產生器將欄位加到範本中。」
> 「下載的範本會自動將子表格置於表單的最下方,若想要移動子表格位置需要自行調整,但**請勿將不同子表格並排排列**,會導致列印報表時出現問題。」
> 「參數中請使用「**單引號**」,且只能使用「 ' 」,不可使用「 ' 」。」

**判讀**|這是 `docs/31 向上設計 backlog` 的典型形狀 ——
使用者想做的事是「把單據排成我公司的格式」,而官方給的答案是
**「去 Word 裡貼參數,注意別用全形引號」**。

⚠️ **但不得宣稱「Ragic 沒給工具」** —— 它有**欄位語法產生器**(點一下複製參數),
那是它自己的緩解。條件①成立的位置是**產物仍是一個要學語法的 Word 檔**,不是「什麼都沒有」。

#### (c) 浮水印是**租戶級設定**,不是逐範本

**來源**|`.../doc/56`(公司設定)

> 「**浮水印**|你可以於浮水印欄位上傳公司商標等圖案,如此一來使用者**下載成 PDF 檔**的時候文件就會加上浮水印。」

#### (d) 其他相關事實

- 多筆下載可選「**儲存至表單的檔案上傳欄位**」或「多個檔案壓成 Zip / 合併成一份」;合併成一份**只支援 PDF、XLSX、PPTX**。
- 可把記錄裡**檔案上傳欄位的 PDF 合併進輸出**(附件併入單據)。
- `合併列印`(輸出 Excel/Word)是**另一個功能**(`doc/42`),與客製列印報表分開 —— 我方已交付的 print-merge 對應的是那一半。

## 1. 目標與範圍

### 1.1 目標

1. **伺服器端產生 PDF**:可下載、可寄送、可存回記錄的檔案欄位 —— 不再只是叫瀏覽器列印。
2. **租戶級浮水印**(parity)。
3. 🔴 **版面設計不寫語法** —— 使用者在**瀏覽器裡**排版,不去 Word 貼 `{d.1002578:html(inline)}`。

### 1.2 不做的事

| 不做 | 為什麼 |
|---|---|
| **DOCX / XLSX / PPTX 範本上傳** | 那是 §0.3(b) 的路。走它就等於接受「使用者要學參數語言」,直接違反第一約束。**代價誠實**:客戶若已有一份 Word 單據格式,我方無法直接吃 —— 這是我們選擇承擔的遷移成本,要在 OQ 講明 |
| 輸出 PNG / PPTX | 沒有需求證據;PDF 與列印才是單據場景 |
| PDF 密碼保護 | 列在 `docs/25` 但**價值可疑**:PDF 密碼在 2026 年不構成保護,而且它會讓「寄給客戶的單據打不開」變成客服負擔。建議降級 P2 並在 OQ 明說 |
| 電子簽章合規(TWCA) | 已裁定 R2(`docs/25` C2) |

### 6.1 與裁定不同的地方(刻意,記在這裡)

**OQ-PDF-2 裁定「獨立 worker / 服務」,M1 落在同一個行程裡。**
理由:Playwright **本來就把 Chromium 跑在另一個作業系統行程**,
所以「當機不連坐」這個真正要的隔離是免費的;獨立服務額外買到的是
**映像檔體積**(Chromium ≈ 300-400 MB)與獨立擴縮 —— 那是部署層的事。

### 7.1 🔴 一個差點出貨的 bug:`UPDATE ... RETURNING` 回的是**新值**

到期清理的直覺寫法是:

```sql
UPDATE pdf_job SET status='expired', object_key = NULL
WHERE ... RETURNING id, object_key
```

而 PostgreSQL 的 `RETURNING` 在 UPDATE 之後回的是**修改後**的內容 ——
於是 `object_key` 全是 NULL、**storage 物件永遠刪不掉**,
而列已標成 `expired`,**看起來一切正常**。改用 CTE 先取舊值再改。

⚠️ **本測試的第一版對這個 bug 是空過的**:它只斷言了狀態與 `object_key IS NULL`,
而兩種寫法下那兩條都會過。真正有鑑別力的只有 `storage.stat(key)` 變成 null。
已補,並以還原成錯誤寫法實測過會紅。

### 7.2 測試harness 的兩個坑

1. **只有一個 actor 的測試表達不出權限缺口**(`pitfall-tenant-scoped-is-not-authorized`)。
   本檔現在有兩個:無角色的 actor 證明「渲染時真的重新解析權限」,
   系統 admin 才測得到明細。
2. 租戶用 drizzle 直接插的話,**系統角色不會自己出現**(正常路徑是 `seedSystemRoles`)。
   少了那一步,指派 admin 的 INSERT 會影響 0 列而且**不報錯** —— 已加 `rowCount !== 1` 即拋。

### 7.3 順手修的 N+1

子表明細第一版把 `listRecords` 放在 `for (parentId)` 迴圈裡 ——
200 筆就是 200 次一模一樣的查詢。改成撈一次在記憶體分組。

### 8.3 裁定與其依據

**頁首 / 頁尾列走 `<thead>` / `<tfoot>`,不是 `break-inside: avoid`。**
面板寫的是「頁首」,而使用者對這兩個字的預期是**每頁重複**;記錄頁上原本
只做到「不被切斷」(螢幕沒有頁,那是極限),而**列印頁是分頁媒體,做得到就要做到**。
2026-08-06 以 45 欄位撐成兩頁的真實產物確認:兩頁都有頁首列與頁尾列。

**欄寬在紙上用 `1fr` 而非固定 60px。** 畫布是 12×60=720px,A4 扣 12mm 邊界只有
~703px,固定 px 會溢出。等分後**比例與 colSpan 完全不變**,只是縮放到紙寬。

**浮水印只做文字,圖片列殘留。** parity 逐字是「上傳公司商標」(`doc/56`),
但站①查出 **`tenants.logo_file_key` 至今零 writer** —— 租戶級資產上傳這條路
根本不存在(`FilesService.upload` 綁欄位型別)。加一個同樣沒有 writer 的
`watermark_file_key` 只是把同一個漂移再犯一次。

**附件合併預設關,且未併入的一定要說。** 「印一張採購單」與「把這張單所有附件
一起交出去」是兩個不同的意圖。靜默略過是本 repo 最常犯的形狀,故 `merge_report`
逐檔記原因(`not-pdf` / `encrypted` / `unreadable` / `too-large` / `unavailable` / `page-cap`),
UI 一定顯示。**`null` 與 `[]` 不可混為一談** —— 前者是「沒要求合併」,
後者是「合併了,全部成功」;混掉的話沒有附件的單據會顯示成「附件全部略過」。

**`@cantoo/pdf-lib` 而非上游 `pdf-lib`。** 解析的是使用者上傳的不可信 PDF,
維護狀態比相依數量重要:上游自 **2021-11-06** 未發版(317 open issues),
fork 近一個月發 5 版(最新 2.8.1,2026-07-30)。**兩者皆 MIT,2026-08-06
逐檔讀 LICENSE 本文確認**(非 `spdx_id`)。
