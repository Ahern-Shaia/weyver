## 4. A1 — 畫布渲染為欄位列（①）

- 設計畫布與填單**共用** `FormSection` / `FieldGrid`；設計模式以 `mode="design"` 開關差異。
- 設計模式的差異**只有三件**：
  1. 值格顯示**示例值**（來源見 OQ-FDW-1），以 `ink-3` + `--color-label` 淡底標示為非真值
  2. 每格可拖（dnd-kit，既有）、可點開設定
  3. 格子邊界可拖以調 `span`
- **不做**兩套渲染 —— 兩套一定會漂移，而「設計即所見」的整個價值就建立在兩者一致上。

## 5. A2 — 就地新增欄位（②）

- 欄位表最後一列為 ghost row `＋ 新增欄位`（虛線框、`ink-3`）。
- 點擊 → **立即插入一格**，游標落在欄名（`contentEditable` 或 inline input）。
- 型別由該格上的 popover 選，**預設單行文字**。
- DDL 觸發時機 → **OQ-FDW-3**。

## 6. A3 / A4 — 型別 popover 與屬性抽屜（③④）

- **型別 popover**：取代常駐欄；分組（文字 / 數值 / 日期 / 選擇 / 關聯 / 進階），
  排序見 OQ-FDW-4。搜尋框保留（既有 palette 已有）。
- **屬性抽屜**：右側單一欄，accordion 四段 —— 基本 / 驗證 / 條件式格式 / 列印。
  同時可見的輔助面板恆為 0 或 1（docs/29 S3）。
- 工具列的「動作/簽核」「列印」「條件式格式」三個開關**移除**，
  改由抽屜與表單級設定入口承接（OQ-FDW-5）。

## 10-quinquies. 🔴 第三輪查證（2026-08-02）—— 生產環境截圖推翻了「設計即所見」的**形式**

### 🔴 A. 「設計即所見」不是兩個頁籤，是**同一個畫面 + 修改設計模式**

截圖一右上角是一顆**「修改設計」按鈕**，不是 `設計 / 填單` 的頁籤切換。
使用者本來就在看那張表，按下去就進設計模式 —— **不是切到另一個頁籤去設計一張長得很像的表**。

與 doc/38 逐字一致：「你可以從**列表頁右上角**點擊 修改設計 來進入列表頁的 設計模式」
（列表頁**自己**也有設計模式 → 證明「設計」是**套在 view 上的模式**，不是一個 view）。

| 連帶推翻 | 說明 |
|---|---|
| **本模組的整個前提** | 我做的是「讓設計頁籤長得像填單頁籤」。正確答案是「**只有一個畫面**」—— 兩天前修的漂移，根因就是我把它做成了兩個東西 |
| **OQ-FDW-1 示例值** | Ragic 設計模式看得到真實資料，因為**你根本沒離開那筆記錄**。官方文件從沒提「設計模式的示例值」—— **這個問題在 Ragic 不存在**，是我造出來的。當時的理由（權限 / 空表）只在「設計是獨立頁籤」的前提下才需要 |

### 🔴 B. IA 上層反了

| | 真實 Ragic（截圖） | 我的 v3 |

### 🔴 C.「工具」是巨型選單 —— 心智模型是**表單就是操作中心**

截圖二 `工具 ▾` 展開為六組 25+ 動作：
**編輯**（編輯多筆 / 大量修改 / 批次執行 / 大量產生 / 大量複製 / 大量刪除）·
**匯出**（Excel或CSV / PDF / 友善列印 / 下載附件 / 客製列印報表）·
**匯入**（從檔案匯入資料 / **用檔案建立新表單** / 多筆編輯上傳 / 定期從網址匯入）·
**分享**（分享 / 嵌入 / 發送E-mail / 發送簡訊）·
**報表**（產生報表 / 合併列印 Word・Excel / 發佈到網路 / 定期寄出報表）·
**同步與通知**（行事曆同步 / SQL 資料庫同步 / 雲端系統整合 / Webhook / 通知設定 / 表單填寫提醒）

**這不是缺功能**（多數我們都有），是 **IA 錯位**：我們把它們散在設定中心各頁，
使用者得**離開表單**才能操作；Ragic 讓針對這張表的所有動作都在**這張表上**做完。

### ⚠️ 連帶：docs/29 S5「水平 header 帶 ≤1」需修訂

真實 Ragic 是**兩條**：頁籤橫列（導覽）+ 工具列（動作）。S5 是我量測**自家臃腫的 3 條**後定的規則，
把「導覽」與「動作」混為一談。**修訂為「導覽 1 條 + 動作 1 條，合計 ≤2；同層不得重複」**，
理由與量測寫回 docs/29。
