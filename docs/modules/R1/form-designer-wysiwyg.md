## 1. 目標與範圍

### 1.1 目標

讓**設計表單時看到的，就是填單時會看到的**。使用者（docs/24：Ragic 範式思考者）
在設計器裡應該一直看著一張單據，而不是一份欄位清單。

### 1.2 範圍內

| # | 項目 | 性質 |
|---|---|---|
| ① | 畫布格子改渲染為**欄位列**（label 格 + 值格 + 示例值），與填單同一套單據語言 | **補完已裁定** |
| ② | **就地新增欄位**：表尾 ghost row → 插入 → 游標落在欄名 | 新 |
| ③ | 型別常駐欄 → **popover** | 新 |
| ④ | 欄位屬性收進**右側單一抽屜**（accordion：基本 / 驗證 / 條件式格式 / 列印） | 新 |

### 1.3 明確不在範圍

- **不動 `form_def.layout` 資料模型**（`form-designer-2d` M1 已建，row/col/span 足夠）
- **不動 DDL / DML 鏈**（版面皆 metadata，與資料層正交 — docs/27 核心洞見）
- **不改草稿模型**（OQ-FD2-2 已裁定：layout 走草稿、結構性即時 DDL 不入 undo）
- **不新增後端端點、零 migration**

### 1.4 量測基準（1440px · 開一張表 · 點一個型別）

### 2.1 🔴 最重要的發現：D1 只實作了一半

`form-designer-2d.md` §0 逐字：「落地 D1 裁定「**2D 格線畫布 = 填單畫面本身**」」。

**實測（Playwright，同一張表切換兩個頁籤）**：

| | 設計頁籤 | 填單頁籤 |
|---|---|---|
| 渲染 | 欄位**卡片**堆疊（欄名 + 型別名） | **全框線欄位表**（label 格 + 值格 + 分段條） |
| 結構 | CSS grid `52px × 12` ✅ | 單據語言 ✅ |

→ **座標系統做了，視覺對齊沒做。** 本模組不是提新設計，是**補完已裁定事項**。

**文件與程式碼都不算錯**（2D 畫布確實做了），漏的是裁定裡的一個子句。

## 3. 剩餘 scope 切分

| 批次 | 內容 | 風險 | 建議 |
|---|---|---|---|
| **第一批** | ① 畫布改欄位列 + ④ 屬性收進單一抽屜 | 中（渲染共用） | 解掉最大兩個斷點，**不動新增流程** |
| **第二批** | ② 就地新增 + ③ 型別 popover | 中高（動到 DDL 觸發時機） | 需先裁定 OQ-FDW-3 |

---

## 4. A1 — 畫布渲染為欄位列（①）

- 設計畫布與填單**共用** `FormSection` / `FieldGrid`；設計模式以 `mode="design"` 開關差異。
- 設計模式的差異**只有三件**：
  1. 值格顯示**示例值**（來源見 OQ-FDW-1），以 `ink-3` + `--color-label` 淡底標示為非真值
  2. 每格可拖（dnd-kit，既有）、可點開設定
  3. 格子邊界可拖以調 `span`
- **不做**兩套渲染 —— 兩套一定會漂移，而「設計即所見」的整個價值就建立在兩者一致上。

## 5. A2 — 就地新增欄位（②）

- 欄位表最後一列為 ghost row `＋ 新增欄位`（虛線框、`ink-3`）。
- 點擊 → **立即插入一格**，游標落在欄名（`contentEditable` 或 inline input）。
- 型別由該格上的 popover 選，**預設單行文字**。
- DDL 觸發時機 → **OQ-FDW-3**。

## 6. A3 / A4 — 型別 popover 與屬性抽屜（③④）

- **型別 popover**：取代常駐欄；分組（文字 / 數值 / 日期 / 選擇 / 關聯 / 進階），
  排序見 OQ-FDW-4。搜尋框保留（既有 palette 已有）。
- **屬性抽屜**：右側單一欄，accordion 四段 —— 基本 / 驗證 / 條件式格式 / 列印。
  同時可見的輔助面板恆為 0 或 1（docs/29 S3）。
- 工具列的「動作/簽核」「列印」「條件式格式」三個開關**移除**，
  改由抽屜與表單級設定入口承接（OQ-FDW-5）。

## 7-bis. 企業級 cross-cutting 檢核

| 面向 | 檢核 | 本模組 |
|---|---|---|
| **安全** | 是否新增資料路徑 | 無。純前端渲染改動；欄位建立仍走既有 `POST /forms/:id/fields`（已有 authz） |
| **權限** | 設計權與填單權分離 | 沿用既有（E-1 動態權限）；**設計模式的示例值不得洩漏他人資料** → OQ-FDW-1 直接關聯 |
| **a11y** | 🔴 拖曳鍵盤替代（#109） | **必須保留**。新增「就地新增」後需補：ghost row 可 Tab 到達 + Enter 觸發；型別 popover 需 focus trap + Esc |
| **a11y** | 對比 | 示例值用 `ink-3`（四種底皆 ≥4.5，CI 已把關）；淡底用 `--color-label` |
| **可靠** | 並發 | layout 並發覆寫防護（#109 已做）不受影響 |
| **效能** | 大表單 | 欄位列渲染成本高於卡片；**≥ 60 欄需量測**，必要時虛擬化（列為 M4 驗收項） |
| **相容** | 既有 layout | row/col/span 語意不變，舊資料直接可讀；**不需要遷移** |
| **觀測** | — | 無新增後端路徑，無新增指標 |

## 8. 測試策略

| 層 | 內容 |
|---|---|
| **量測型 e2e**（新） | 三條 docs/29 不變量：header 帶 ≤1、輔助面板 ≤1 欄、主體佔比 ≥60%。**這是本模組的主要驗收** |
| **一致性 e2e**（新） | 同一張表：設計頁籤與填單頁籤的**欄位順序、label 文字、分段結構**必須逐一相同 |
| e2e（既有） | `designer.spec` 全綠（拖曳、undo、儲存版面）—— 不得因改渲染而失效 |
| e2e（新） | 就地新增：ghost row → 打字 → 欄位出現在畫布**該位置**；鍵盤路徑同樣可完成 |
| 單元 | 示例值產生器（依型別）；型別 popover 排序 |
| 視覺 | 設計 / 填單兩張截圖的欄位表區域**結構相同** |
