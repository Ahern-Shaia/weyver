## 3. 🔴 字級:v3 不能照搬,而理由是量出來的

### 3.1 量測(v3 五個畫面,逐元素)

| px | 數量 | mono 佔比 | 實際內容 |
|---:|---:|---:|---|
| 12.5 | **237** | 21% | 介面主體 |
| 11 | **119** | 57% | 「最久 6 天」SLA 時效 |
| 12 | 96 | 23% | 數字 |
| 11.5 | 85 | 38% | 「筆」 |
| 13 | 84 | 12% | 動作、標題 |
| 10.5 | 81 | 53% | 「天」單位 |
| 10 | 39 | 44% | 「無人認領」「含 CAPA」徽章 |
| 9.5 | 24 | 29% | 「主表」徽章 |
| 9 | 5 | **100%** | `REF` `TEXT` `DATE` 型別代號 |
| 其餘 | 各 ≤14 | — | 14.5 / 15 / 16 / 17 / 20 / 22 / 24 / 26 |

### 3.2 結論:**v3 有 19 種字級**

而現行白名單存在的理由,逐字是「原本 **16 種混用**、65% 低於 12px」——
**v3 在這條軸上比當初被修掉的狀態更糟。**

→ **v3 裁定的是視覺方向,不是字級表。** 照搬會把一個已經解掉的問題放回去。

### 3.3 但地板也不能原封不動

現行地板 12px 的依據是 **Carbon caption-01 / Fluent Caption1**。
而 v3 的 9–11px 帶**有一半以上是 mono**,內容是**識別碼 / 徽章 / 單位** ——
那不是散文,是**標籤**。把標籤和內文套同一條地板,是規則過度概化。

→ 建議見 **OQ-V3-2**。

## 3-bis. 🔴 B 的真正風險不是功能退步,是「v3 沒畫的狀態」

決策方問:「用現有的元件、只換視覺,還是會讓功能退步的風險無法控制嗎?」
—— **不會**。那句是掛在 **C(整個重寫)**,不是掛在 B。
而且 **B 已有實測證據**:圓角那次(`8d4832d`)改 1 個檔案 4 個值,
全站生效、功能零影響、`color-literal` 綠。

**但量了狀態覆蓋之後,風險換了位置。**

### 3-bis.1 七份產品稿的狀態覆蓋(逐檔量)

| 稿 | hover | disabled | error | loading | empty |
|---|---:|---:|---:|---:|---:|
| Workspace | 5 | **0** | **0** | 0 | 0 |
| Form Designer | 6 | **0** | **0** | 0 | 0 |
| Form Builder | 3 | **0** | **0** | 2 | 0 |
| Home v2 | 7 | **0** | **0** | 0 | 1 |
| Template Library | 1 | **0** | **0** | 0 | 0 |
| Table Empty | 2 | **0** | **0** | 0 | 1 |
| Login | 3 | 2 | **0** | 14 | 0 |
| **Brand Board** | **13** | 0 | **3** | **8** | 0 |

### 3-bis.2 結論

**產品稿只畫了 happy path 的一格。** 狀態規範**集中在品牌板** ——
決策方**有想過狀態,只是寫在品牌板、沒畫進產品稿**(§14 Loading 四態、
Alert/Toast/Dialog/Drawer 的職責分工表都在那裡)。

→ **重構的漂移入口在這裡**:元件有 disabled / error / 空 / 載入,
而產品稿沒有對應的樣子,只能「推導」。
🔴 **而它不會被 e2e 抓到** —— 功能還在,只是 disabled 長得不對。

### 3-bis.3 對做法的影響

1. **M3 元件層的驗收條件改寫**|不是「長得像 v3」,是
   「**每個元件的每個狀態都指得出出處**」—— 出處是產品稿 or 品牌板 or 明確標為推導。
   指不出出處的推導要當場記下來,不能默默決定(這正是 `docs/38` 的 D5 構造規則)。
2. **狀態清單先於樣式**|M3 開始前先對每個元件列出它實際有的狀態
   (從 `packages/ui` 的 props 與 variant 掃出來,不是憑印象),再去對稿。
3. **品牌板要進 M3 的輸入**|它不是「品牌文件」而已,它是**狀態規範的唯一來源**。

## 8. 落地紀錄 — M2 字級(2026-08-08)

### 8.1 做法:給它一個名字,不是給白名單多加一個數字

OQ-V3-2=C 的「標籤軌 11px」**沒有**做成「白名單多允許 11」——
那又是一個 magic number,下次照樣漂。改為具名 token:

```
--text-tag: 11px;   /* 徽章 / 型別代號 / 單位 / kicker —— 不得用於句子 */
```

`text-[11px]` **維持禁用**。要用標籤軌就寫 `text-tag`,而名字本身就說明了它的邊界。
⚠️ 9 / 9.5 / 10 / 10.5 **不採**(§3.2:v3 有 19 種字級,照搬會把已解掉的問題放回去)。

### 8.2 13 處紅燈依角色分流,不是一律放行

| 角色 | 數量 | 處置 |
|---|---:|---|
| 徽章(`rounded-xs border px-1` 的 chip 形狀)+ kicker | 8 | → `text-tag` |
| **句子**(「由範本定義推導,與實際建出來的一致」「套用後可從資源回收桶還原。」)+ 短標 | 5 | → **`text-[12px]`**,散文地板不放行 |

### 8.3 🔴 第一版取名 `--text-label`,造成雙重靜默退步

Tailwind 的 `text-*` **同時服務顏色與字級**,而本庫已有 `--color-label`,於是:

```
.text-label { color: var(--color-label); }   ← 顏色贏了
```

**8 個徽章同時掉了字級、而且顏色被改掉 —— 完全不報錯。**

⚠️ **我的第一個探針給了假陰性**:用 `getComputedStyle` 量執行期插入的元素,
量到 14px 以為「utility 沒生成」—— 其實是 **Tailwind JIT 只為原始碼裡出現過的 class 生成**。
**是去查產生的 CSS 規則(`document.styleSheets`)才看到真相。**

→ 改名 `--text-tag`,實測 `.text-tag { font-size: var(--text-tag) }` 正確。
→ **加了 CI 檢查**:`--text-X` 不得與 `--color-X` 同名,
   並用「壞的應該紅」驗過(注入 `label` → 確實紅)。

### 8.4 驗收

`type-scale` + `color-literal` + 撞名檢查 **6 條全綠**(先前 type-scale 紅了一天)。
