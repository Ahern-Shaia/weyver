## 1. 目標與範圍

### 1.1 目標

1. **連結欄可以用** —— 填單時搜尋並選取目標記錄,不是打 id。
2. **選不到看不到的東西** —— 候選清單先過目標表單的 `view` 權,且後端再驗一次。
3. Load 帶入(M2):選取當下把來源欄值**複製**進本記錄,存檔前可改。

### 1.2 不做的事

- ❌ **網格內選記錄** —— 需 `glide-data-grid-cells`(未安裝)。網格維持文字。
- ❌ **多選連結** —— Ragic 官方明載多選後不支援載入欄位(§0.3-8);先做單選。
- ❌ **同步為最新資料** —— 獨立議題,且 Ragic 自己有 500 筆上限(§0.3-6)。
- ❌ **子表格載入** —— Ragic 光是這一項就列了 3 類共 12 條限制(§0.3 原文),自成一個模組。
- ❌ **M2M junction** —— `formula-and-linkload` M3 的另一項殘留,不在此。

## 3. M1 設計(選記錄 + 可讀顯示)

### 3.1 端點

`GET /api/forms/:formId/fields/:fieldId/link-options?q=&limit=`

- `@RequiresFormAction("view")` 於**來源**表單(你在填這張單)
- 🔴 **再驗目標表單的 `view`** —— 來源權限不蘊含目標權限。沿用 `WidgetService` 的做法:
  候選先過濾,且後端是執法點(**只在前端過濾等於沒做,直接打 API 就能繞**)
- 回 `{ id, label }[]`,`label` 取目標表單的**標題欄**(第一個可讀 text 欄)
- 🔴 label 必須走 `maskRead` 同一條路徑 —— 若標題欄對此人隱藏,回 `#id` 而非欄值

### 3.2 唯一性(Ragic §0.3-1)

Ragic 要求連結目標欄唯一。我方 link 值是**記錄 id**(天生唯一),故此約束**在資料層已滿足**;
唯一性的真正意義是**給人看的辨識度** → 落在 label 選擇上,不是約束條件。
⚠️ 這是與 Ragic 的**刻意差異**,理由是我們的連結錨在 id 而非欄位值 —— 記錄改名不會斷連結,Ragic 會。

### 3.3 UI

沿用 `MemberInput` 的形狀(同為「搜尋 + 選一筆 + 顯示名稱」),不另創語彙。

## 7-bis. M1 出貨紀錄(2026-08-04)

### 落地中翻掉的一件事

🔴 **連結欄在前端本來就被列為 stub。** `STUB_TYPES` 逐字是 `["link"]`,
填單畫面顯示「(此型別即將推出,暫不可填)」——
而 `formula-and-linkload` 的檔頭同時寫著「Link&Load SHIPPED」。

👉 **UI 一直說實話,是模組文件在過度宣稱。**
`STUB_TYPES` 這個機制的價值正是**讓畫面誠實**:寧可說「還不能填」,
也不要給一個填了沒反應的框。故常數保留(清空但不刪),下一個「後端先行、前端未跟上」的型別還會用到。

### 🔴 送出邊界的靜默丟值(實走才發現)

`toSubmitValue` 沒有列 `link` → 落到 default 的字串分支被丟掉:
**畫面上明明選了供應商,存進去卻是 `null`,而且沒有任何錯誤。**

⚠️ **`member` 欄踩過同一個坑(#96),`value.ts` 裡有一段註解逐字寫著** ——
而 link 還是踩了,因為那條規則只寫在註解裡,**沒有任何機制在漏列時發出訊號**。
兩次都是**瀏覽器實走**才發現的:單元測試不會送出、型別上 `unknown` 一路綠燈。

`value.test` 原本斷言 `toSubmitValue(field("link"), 5)` 為 `undefined` ——
**那條斷言在釘住 bug**(它當時是「link 是 stub」的正確表述,型別解禁後就變成護欄)。

### 移出 stub 的連帶(三處)

| 處 | 為什麼要跟著改 |
|---|---|
| `palette.tsx` | 原本硬寫 `[...ADVANCED_TYPES, "link"]` 補進來(stub 時期的 workaround),link 進 ADVANCED 後會**重複出現** |
| `isGridEditable` | 要**顯式排除** link —— 網格內沒有選記錄器,開放編輯等於讓人在格子裡打目標記錄的 id,**那正是填單頁剛移除的東西,不要從另一個門放回來** |
| `singleSelect` 的 `aria-label` | `record-workbench` 用整頁 `getByRole("combobox")`,而連結欄的選記錄器**也是 combobox** |

### ⚠️ 試了又收回的:欄位輸入的無障礙名稱

欄位輸入框在無障礙樹上**沒有名字**(視覺欄名是旁邊的 div,無 `<label for>` 關聯,
螢幕閱讀器只唸「編輯文字」,WCAG 4.1.2)。補上 `aria-label` 之後
**量到的波及面是 27 條 e2e** —— 現行多數 spec 拿 placeholder 推導出的無障礙名稱
當錨點(如 money 欄的 `0.0000`)。

修法是對的(placeholder 一打字就消失,拿它當名稱是反樣式),
但它是一件**獨立的 a11y 工作**,不該夾帶在別的 commit 裡順手做掉。已還原,
`field-input.tsx` 留下說明與量到的數字。

## 7-ter. M2 出貨紀錄(2026-08-04)

### 設計決定與依據

| 決定 | 依據 |
|---|---|
| Load 在**選取的當下**、寫進 form state | Ragic `doc/14` 逐字提到「**未儲存**」狀態(OQ-LNK-1) |
| 對映以 **field id** 存,不用欄名 | 沿用 `formula_def.depends_on` 的理由:**id 穩定於改名**。用欄名的話,來源表單改個欄名就靜默斷掉,而畫面上看不出來 |
| 對映**在後端解讀**,回「本地欄名 → 值」 | 讓前端自己查 `fromFieldId` → 欄名的話,那份查表邏輯遲早與後端漂移 |
| 設定 UI 用**成對下拉**而非 Ragic 的連連看 | **刻意差異**:連連看的價值在一次看到全貌,而我們的欄位清單本來就在同一畫面上;成對下拉還能鍵盤可達、窄螢幕可用 |

### 🔴 帶入是第二個洩漏面

`link-options` 只回 `{id, label}`;**帶入是把別張表的欄值搬到這張表**,面更大。三道防線:

1. 目標表單 `view` 權必查
2. **取值走 `getRecord` 而不是自己寫 SQL** —— `getRecord` 已套 `maskRead`(含 2026-08-04 的公式污染閉包),
   來源欄若對此人隱藏就**根本不會出現在回傳裡**。自己查表等於繞過遮罩。
   ⚠️ Ragic 對同一風險的解法是「**設定了欄位層級存取權限的欄位不准當連結欄位**」(`doc/14`)——
   **它用禁止,我們用遮罩**,兩者都不讓值漏出去,但我們的欄位仍可當連結欄。
3. 設定對映時**兩端都驗歸屬** —— 綁了租戶不等於這個欄位屬於這張表。
   少了它,帶著自己有 `design` 權的 `formId` 就能把**任意兩個欄位**配成對映,
   下次有人選記錄時那個值就會被讀出來。整合測專釘這條。

### 兩個「不做什麼」的決定

- **來源欄被遮罩時不帶入**,而不是帶入 `undefined` —— 後者會把使用者原本填的值清掉,是靜默的資料遺失。
- **清除選擇時不清空已帶入的值** —— Ragic 對子表格的規則逐字是「不會自動清除或覆蓋原有資料」。

### 前端的結構性障礙

`FieldInput` 的 `onChange` **只改自己那一欄**,而 Load 天生要寫兄弟欄位。
新增 `onLoadMany` 回呼,兩個消費端(填單面板 / 記錄頁編輯)各自接自己的 setter;
`use-record-edit` 補 `setFields`(逐欄呼叫會連續觸發多次重繪)。

⚠️ e2e 釘的是**跨欄位的副作用**(選 A 欄會改 B 欄)——
單元測試看不到那個,那是 form state 的整體行為,只有實走看得到。
