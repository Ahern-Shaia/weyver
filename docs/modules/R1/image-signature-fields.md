### 0-bis.1 台灣《電子簽章法》條文(一手逐字)

**出處**|全國法規資料庫 `https://law.moj.gov.tw/LawClass/LawAll.aspx?PCode=J0080037`(查證 2026-08-03)。**最新修正日期:民國 113 年 05 月 15 日**。

| 條 | 逐字條文(節錄) |
|---|---|
| **第 2 條**(定義)| **電子簽章**:「依附於電子文件並與其相關連,用以辨識及確認電子文件簽署人身分、資格及電子文件真偽者」<br>**數位簽章**:「屬於電子簽章之一種,指將電子文件以數學演算法或其他方式運算為一定長度之數位資料」<br>**憑證機構**:「指簽發憑證之機關、法人」<br>**憑證**:「指載有簽章驗證資料,用以確認簽署人身分、資格之電子形式證明」 |
| **第 4 條**(法律效力)| 「電子文件及電子簽章,符合本法規定者,在功能上等同於實體文件及簽章,不得僅因其電子形式而否認其法律效力。」 |
| **第 6 條**(數位簽章推定)| 以數位簽章簽署電子文件,符合下列各款規定者,**推定**為本人親自簽名或蓋章:<br>· 使用經主管機關許可之憑證機構簽發之憑證<br>· 憑證未逾有效期間及其使用範圍 |

**兩層結構(事實層面之整理,非法律結論)**

- **第 4 條層**|不因「是電子的」就否認效力。此為**否定式保護**,不等於賦予任何證明力。
- **第 6 條層**|唯有**數位簽章**(私鑰運算 + 主管機關許可之憑證機構所簽發、且在有效期間與使用範圍內之憑證)才取得「**推定**為本人親自簽名或蓋章」的地位。「推定」意謂舉證責任移轉,仍可反證推翻。

**對 R1 簽名欄之事實描述(非法律結論)**

| 事實 | 依據 |
|---|---|
| R1 簽名欄的產出物是 **PNG 點陣圖 + 檔案 metadata**,經既有上傳管線存於物件儲存 | 本檔 §4.1 / §4.4;OQ-IS-5=A |
| 該流程**不含**私鑰運算,**不含**任何憑證機構簽發之憑證 | 本檔 §1.2 已明列合規簽章屬 R2 |
| 故就第 2 條之定義而言,R1 簽名欄**不構成「數位簽章」**,因而**不落入第 6 條之推定** | 條文文義比對 |
| 是否構成第 2 條之「電子簽章」,取決於個案上該圖片是否「足以辨識及確認簽署人身分、資格及電子文件真偽」—— **本模組不對此下結論**(涉個案認定,須律師意見) | 誠實標注 |

⚠️ **未查證**|(a)《電子簽章法施行細則》與主管機關(數位發展部)之函釋、公告排除適用範圍;(b) 各業別特別法(如稅務憑證、勞動契約、醫療紀錄)對簽署方式之額外要求;(c) TWCA 是否為「經主管機關許可之憑證機構」及其許可範圍 —— **docs/23 v6.1 C2 以 TWCA 為 R2 標的,此點須於 R2 M0 前補查**。

### 0-bis.4 產品 UI 是否須對使用者明示 —— 建議:**須明示**

**現況**|FMEA S2 的緩解是「UI 全程**無**『已簽署 / 具法律效力』字樣」,即 **不作虛假宣稱**。**但「不宣稱」≠「有明示」** —— 使用者仍可能自行腦補效力。

**建議明示之理由(三條)**

1. **可預見的誤用**|本平台之定位是「取代 ERP」,簽名欄的自然使用場景就是驗收單、領料單、點交單。使用者把它當正式簽核憑證使用**是可預見的**,而非離奇誤用。
2. **責任面**|沉默使產品成為誤解的共同來源;明示把「這是畫押圖片、不是數位簽章」變成使用者已知的事實,並留下可稽核的告知紀錄。
3. **與 sober 品牌語氣一致**|docs/26 之聲音語氣為 sober;誠實標注能力邊界正是該語氣的實踐,且與 AGENTS「不宣稱做不到的事」同源。

**建議做法(最小、不喧賓奪主)**

| 位置 | 內容 |
|---|---|
| **設計器**|建立 `signature` 欄時,欄位設定面板顯示一行說明:「本欄儲存手寫簽名圖片,不含數位憑證。需具法律推定效力之簽署請改用合規電子簽章(尚未提供)。」 |
| **填單 / 記錄頁**|簽名板旁一行次要文字級說明,**不使用**驚嘆號、警示色或彈窗(避免每次填單都像出錯) |
| **不做**|❌ 不加「已簽署」徽章 ❌ 不加鎖圖示 ❌ 不加確認對話框 —— 這些都會製造 OQ-IS-8=A 明確拒絕的「沒有密碼學支撐的安全感」 |
| **文件**|客戶說明文件與客服 FAQ 引用 §0-bis.3 表,不另撰口徑 |

**OQ-IS-8 重裁 → ✅ A′(已裁定並落地 2026-08-03)**

> 採納下列建議。已實作:`signature-input.tsx`(填單 / 記錄頁,簽名板下方)
> 與 `field-settings.tsx`(設計器,`type === "signature"` 時)各一行次要文字級說明,
> **無驚嘆號、無警示色、無彈窗、無鎖圖示、無「已簽署」徽章**。
> §12 FMEA **S2 由 ✅ 降回待辦後已重新達成** —— 緩解點由「design doc 有寫」
> 改為「**使用者看得到**」。
>
> 裁定理由中最重的一條:**風險發生在使用者端,緩解也必須落在使用者端。**
> 原 A 的「明文化」只落在 design doc 與元件註解,那對客戶而言等於不存在。

#### 原建議(保留作對照)

> 現行裁定 A =「明文化為『畫押圖片』,不宣稱不可否認性」。
> **建議升級為 A′ =「不宣稱 **且** 於 UI 明示邊界」** ——

## 1. 目標與範圍

### 1.1 目標(P0)

1. **`image` 欄型**|獨立於 attachment;值沿用 `[{key,name}]` 契約;填單可上傳多張、縮圖預覽、移除;記錄頁 / 清單 / 列印顯示縮圖。
2. **`signature` 欄型**|canvas 手寫板 → PNG → 走既有上傳管線;單張;可清除重簽;記錄頁顯示簽名圖。
3. **上傳型別收斂**|`image` / `signature` 欄只接受影像類 MIME(不是「attachment 能接什麼都能接」)。
4. **零 migration**|兩型皆 `jsonb` 欄(同 attachment),新欄型只是 registry 加項 —— 既有表零遷移。

### 1.2 不做的事(scope 邊界)

- ❌ **伺服器端縮圖(Sharp)**|見 OQ-IS-4;P0 以顯示尺寸限制替代,原圖直出。
- ❌ **EXIF 剝除**|需影像處理相依,與縮圖同批 → P1(§12 S4 明列隱私殘留)。
- ❌ **合規電子簽章(TWCA / 不可否認性 / 時戳)**|docs/23 v6.1 C2 已裁定 → **R2**。本模組只做「畫押圖片」,**不宣稱法律效力**(OQ-IS-8)。
- ❌ **Ragic 之簽名背景圖 / 載入預製簽名 / 移除邊界空白**|OQ-IS-7 → P1。
- ❌ **HEIC/TIFF**|magic bytes 白名單未含(iPhone 原生格式需轉檔相依)→ P1,與縮圖同批。**(2026-07-28 更新:F-7 裁定伺服器端**永不**支援 HEIC —— HEVC 專利池明文對雲端服務按用戶計費;改以前端 `accept` 觸發 iOS Safari 自動轉 JPEG,並提供明確錯誤指引。)**
- ❌ **Glide 網格內編輯圖片/簽名**|同 attachment,網格不可 inline 編輯(僅顯示有無)。

## 4. 設計要點

### 4.1 欄型定義(M1)
```ts
image:     { dbFieldType: "jsonb", valueSchema: [{key,name}] max 20, optionsSchema: { maxHeightPx? } }
signature: { dbFieldType: "jsonb", valueSchema: [{key,name}] max 1,  optionsSchema: { penColor?, heightPx? } }
```
- 與 attachment **同契約**(OQ-IS-2)→ file-storage 之綁定 / 配額 / 孤兒回收 / 下載權限**零改動**即適用。
- `signature` 以 `max 1` 表達「單張」語意(而非另立契約)。

### 4.2 上傳型別收斂(M1;安全)
`FilesService.upload` 目前只驗「欄位是 attachment 型」。改為依欄型決定允許的 MIME 集合:
- `attachment` → 現行完整白名單
- `image` / `signature` → **僅 `image/*`**(png/jpeg/gif/webp)
不符即 415。理由:圖片欄收到 PDF 會在 UI 破圖,且擴大了該欄的攻擊面。

### 4.3 預覽取得方式(M2/M3;技術約束)
下載端點固定 `attachment` disposition + `application/octet-stream`(docs/22 防 HTML/SVG XSS,**不放寬**)。
預覽走既有 `fetch → blob → URL.createObjectURL`(dev 需帶租戶標頭,本就得走 fetch),並於元件卸載時 `revokeObjectURL`。

### 4.4 簽名擷取(M3)
canvas + Pointer Events(滑鼠/觸控/手寫筆統一事件模型)→ `canvas.toBlob("image/png")` → 既有上傳端點。
`devicePixelRatio` 縮放避免高 DPI 模糊;`touch-action: none` 防止畫線時頁面捲動。
