## 1. 總架構(五層)

```
┌─────────────────────────────────────────────────────────────┐
│  ERP 表單 app 層(J–R 的單據全是引擎上的表單)                    │
│  採購單/銷貨單/傳票/工單/BOM/報關單/薪資單… = Tier-2 動態表     │
├─────────────────────────────────────────────────────────────┤
│  calc-binding 語意綁定層(R2/calc-binding-layer.md APPROVED)   │
│  calc_binding + binding_role_map|L1 語意角色 + L3 ZEN 決策     │
│  觸發=狀態轉換(OQ-CBL-4)|fail-closed 驗證(OQ-CBL-8)          │
├──────────────────────────────┬──────────────────────────────┤
│  計算引擎層(docs/18,自研)     │  領域引擎(docs/20,採用)        │
│  GL 過帳/期結/財報 · AP/AR 沖帳 │  GoRules ZEN(決定規則,MIT)   │
│  /帳齡/三方比對 · 庫存估值      │  DBOS(durable 長流程)         │
│  加權/移動/FIFO · FX · 標準成本 │  BullMQ(批次熱點)             │
│  +差異+BOM 結轉 · 折舊 · MRP   │  TigerBeetle=escape hatch     │
├──────────────────────────────┴──────────────────────────────┤
│  R1 表單引擎 substrate(SHIPPED)                               │
│  動態 schema/DDL 安全鏈/RLS/簽核/事件觸發/權限/通知/公式         │
└─────────────────────────────────────────────────────────────┘
```

**三條不變式**(全文件與各 M0 共用):
1. **一切皆表單**|ERP 模組不得建繞過引擎的獨立資料面(計算層熱點批次除外,docs/18 §9);保 audit / 權限 / 公式一致。
2. **綁定自助化**|「算」接到用戶自建表單的路徑 = 語意標記 + 模板 + AI 提議人核准,**逃生門不落到寫程式 / 顧問配置**(第一約束)。
3. **AGENTS 鐵則直通**|金額 `numeric` · 傳票不可變(錯開沖轉)· 過帳單一 tx · 每查詢綁租戶 · SoD。

## 3. 依賴圖

```
calc-binding(M1–M7,R2 第一件事)──┐
                                  ▼
J.gl ◄── J.ap-ar ◄── K(收貨/出貨產生估值+應付應收過帳)
  ▲            ▲        ▲
  │            │        └── M(批號/效期 → K 估值層與追溯)
  │            └── O(發票 ↔ AR/AP 憑證)· P(關稅 → 進貨成本)
  └── N(成本結轉傳票)◄── L(工單/BOM/委外 → 材料/工時)◄── K(領退料)
R(獨立;薪資過帳傳票 → J.gl,弱耦合)
G 連接器(銀行對帳檔 → J 銀行對帳;政府 API → O)
Q(onboarding 匯入,一次性;依 OQ-R2M-1)
```

**讀法**|箭頭 = 「消費其產出」。**J.gl 是全圖的匯點**:K/L/N/O/P/R 最終都產生傳票 → 一切過帳走同一條 calc-binding → GL pipeline,**不允許各模組自帶過帳邏輯**。

## 4. 共用地基(計算層原語,任一模組 M0 不得重複自建)

| # | 原語 | 內容 | 出處 |
|---|---|---|---|
| 1 | **過帳 pipeline** | 綁定驗證(fail-closed)→ 借貸平衡 → 單一 tx 寫分錄 → audit;冪等 key | docs/18 §0/§1 · OQ-CBL-5/8 |
| 2 | **期間管理** | 租戶級會計期間 registry + 期間鎖(已鎖不得過帳)+ 期結 workflow(DBOS)| docs/18 §1.3 |
| 3 | **不可變 journal** | 分錄 append-only,錯誤開反向沖轉;無 UPDATE/DELETE 路徑 | AGENTS 鐵則 4 |
| 4 | **金額精度** | `numeric` + 每幣別小數位 + 明確捨入點(進位差額歸尾) | docs/18 §0 |
| 5 | **多幣別三元組** | 金額+幣別+匯率;期末 FX 重估批次 | docs/18 §4 |
| 6 | **數量/單位換算** | 採購單位↔庫存單位↔BOM 單位;估值以基準單位 | K/L/N 共用 |
| 7 | **批號/序號身分** | 批次為一等公民(M);估值成本層與追溯共用同一批號鍵 | docs/34(FSMA 204 多對多投入產出)|
| 8 | **outbox** | 跨模組副作用(如 K 出貨→J 過帳)crash 不丟事件 | AGENTS ⚙️ 可靠 |
| 9 | **不變量對帳 job** | 試算恆平衡 / 庫存量=異動帳 / AR-AP=GL 明細,定期斷言告警 | AGENTS ⚙️ 可靠 |
| 10 | **ZEN ruleset 治理** | per-tenant JDM 版本化 + 人核准 + audit(科目/稅率/關稅/薪資規則共用)| docs/20 §2 · OQ-CBL-7 |

## 5. 🔴 R1 預留地基清單(design-ahead 的最大回報)

> 逐項 = 「R1 現在就該預留什麼」。**對碼欄為快照推定,各項動工前先 grep 驗證**([[pitfall-stale-todo-already-done]]:待辦有很高比例早就做完了)。

| # | 預留 | R2 誰要用 | R1 現況(2026-08-08 推定)| 若不預留的代價 |
|---|---|---|---|---|
| P1 | **狀態轉換事件可訂閱**(record 狀態機轉換發事件)| calc-binding 觸發(OQ-CBL-4)| event-triggers + 簽核已 SHIPPED,**轉換事件語意是否夠細待對碼** | R2 起跑先回頭改 R1 事件模型 |
| P2 | **破壞性 DDL 前 re-validation hook**(改欄型/刪欄前詢問外部註冊者)| OQ-CBL-3(綁定失效阻擋)| DDL 安全鏈 SHIPPED,**無外部 veto 擴充點(推定)** | 用戶改欄位 → 綁定靜默壞 → 過帳錯帳 |
| P3 | **表單級不可變語意**(僅新增、修改=沖轉)| 傳票 / 分錄 / 發票號 | 引擎記錄可改可刪(soft delete)| 傳票可被改 = 鐵則 4 違規,審計不過 |
| P4 | **金額欄位 = numeric + 幣別小數位** | 全部 | field-types-parity SHIPPED,**currency 型別精度實作待對碼** | 錯了要 data migration,越晚越貴 |
| P5 | **多幣別三元組欄位型別**(金額+幣別+匯率)| J/K/P | 推定未有(單幣金額欄)| 客戶已建表單無法升級為多幣別 |
| P6 | **批號/序號欄位型別 + 追溯查詢** | M/K/L | 推定未有 | 食品 pilot 的追溯需求落空 |
| P7 | **期間鎖攔截點**(寫入前檢查過帳日所屬期間)| J 期結 | 無 | 期結後仍可回頭改帳 |
| P8 | **outbox 基礎設施** | 跨模組副作用 | 通知模組已有 delivery 表,**通用 outbox 待對碼** | 各模組自造半套,crash 丟事件 |
| P9 | **SoD 於權限模型的表達位**(動作級互斥)| E SoD(R2 release)| authz 三層 + 動態權限 SHIPPED,無互斥矩陣 | R2 硬塞 → 權限模型重工 |
| P10 | **記錄級 audit 讀取面**(誰在何時改了哪欄)| 全部(合規)| ddl_audit 有;記錄級 audit 待對碼 | 內控報表無資料源 |

**處置建議**|P1–P4 屬「R1 還在熱、現在補最便宜」→ 各開小項進 R1 backlog(OQ-R2M-4);P5–P10 記在此處,等對應模組 M0 時對碼確認再排。

## 6. 進場順序(M0 開檔計畫)

| 輪次 | M0 | 前置 | 理由 |
|---|---|---|---|
| 1 | **J.gl 總帳**(design-ahead)| calc-binding 已 APPROVED | 全圖匯點;合規最敏感;所有其他模組的過帳目的地 |
| 2 | **K 進銷存 + 估值** | J.gl M0 | 第二個「算」;食品 pilot 直接需求(批號/效期與 M 相依處先立介面)|
| 3 | **L 生產 + N 成本**(可同輪)| K M0 | N 依 J+K+L;L 委外為食品加工硬需求 |
| 4 | O 發票合規 · M 品保追蹤 | 可獨立 / 依 K | O 外部 API 為主;M 與 K/L 介面清楚後進場 |
| 5 | P 進出口 · R HR · G 連接器 | — | 相對獨立 |
| — | Q | 依 OQ-R2M-1 | 收斂後可能降為「onboarding 匯入」小模組併入既有匯入機制 |
