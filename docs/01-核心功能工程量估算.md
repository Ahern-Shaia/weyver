# Ragic 核心功能工程量估算

> **背景**|策略會議討論用文件。評估「以 Ragic 為基底,自研整合 ERP 全功能」的 SaaS 產品是否可行。
> **範圍**|僅拆解「複製 Ragic 核心功能」的工程量。ERP 領域邏輯(GL、進銷存、生產、發票合規)為另一份估算。
> **單位**|一位資深工程師一個月產能 = 1 人月。
> **兩個尺度**|`MVP 人月` = 能上線收第一批客戶的最低量;`對標 Ragic 人月` = 達到 Ragic 目前市場水準。

## 團隊 scaling 換算

> 已納入 Brooks's law:實際比理論慢 20–30%(溝通成本 + onboarding)

| 團隊規模 | MVP 上線 | 對標 Ragic |
|---|---|---|
| 5 人(3 資深 + 2 中階) | **~28–34 個月**(2.5–3 年) | ~54–60 個月(4.5–5 年) |
| 8 人(5 資深 + 3 中階) | **~21–26 個月**(1.8–2.2 年) | ~34–40 個月(~3 年) |
| 12 人(含 2 mobile、2 前端 grid 專家) | ~15–18 個月 | ~24–28 個月 |

⚠️ **這還沒算 ERP 領域邏輯**(GL、進銷存、生產、發票合規)—— 另一份估算,MVP 至少再加 60–100 人月。

## 三個 talking points 給策略會議

### 1. 地基三個模組決生死
Module 1 + 2 + 3(多租戶動態 schema、Grid 引擎、公式引擎)加起來就 **~75 MVP 人月 / ~120 對標人月**,佔總量 40%+。這三塊做不好整個產品廢掉。

**強烈建議 Grid 引擎採 AG Grid Enterprise 授權**(約 US$1,500 / dev / 年),可以砍掉 8–10 人月,回本超快。

### 2. 人才風險 > 錢的風險
公式引擎、動態 schema、Grid 這三塊要有做過 compiler 或 spreadsheet 的資深工程師。台灣市場非常稀缺。

**找不到人 = 時間表 x2**。這是最大的隱藏風險。

### 3. 可以先做「不完整版本」上線收現金
MVP 的 168 人月裡,其實表單引擎 + 關聯 + 基本權限 + 基本報表(約 **90 人月**)就能收第一批客戶。

剩下 78 人月是 mobile、進階公式、BI、稽核 —— 可以邊收費邊做。

這個切法能讓專案在 **第 12–15 個月見到營收**,而不是等到 24 個月才有第一塊錢。
