## 0. 診斷|現況修完了「錯」,但沒有「主意」

### 0.1 程式碼審計的結論:工程層是成熟的,不是問題所在

讀完現行 code,以下資產**評估為正確且不應放棄**:

| 資產 | 現況 | 判定 |
|---|---|---|
| Token 架構 | v4.0:Radix 12 階冷中性 + `--base-brand` 唯一來源 + `color-mix` 推導 + 三主題白牌 | ✅ **保留** —— 這是白牌承諾的工程基礎 |
| CI 執法 | `contrast.test.ts`(四種底逐一驗)· `color-literal.test.ts`(禁 raw hex)· 字階掃描含 CSS | ✅ 保留 —— 「規則沒有檢查就會漏」的教訓成本已付過 |
| 殼語言 | docs/29 五規則(邊框 ≤6% / 層級靠面 / 面板 ≤1 / 主體 ≥60% / header 帶 ≤1),v4 已落地 | ✅ 保留 —— 量測型結論,不因方向change而失效 |
| 動效 | Carbon productive token(70/110/150ms) | ✅ 保留 |
| a11y | focus ring / WCAG 1.4.12 捲動 / reduced-motion | ✅ 保留 |

### 0.2 那病根是什麼

三次 review 的原話是「**太緊密、雜亂、像公司內部後台、沒有品牌感**」。前兩項(緊密、雜亂)已由 v4 + docs/29 以量測修掉(邊框密度 19.6%→合規、色彩有了模型)。**但「像內部後台、沒有品牌感」不是量測能修的** ——

現行規範的全部條文是**減法**:禁陰影、禁 pill、禁漸層、降邊框、收字階、動效收斂。減法能保證「不廉價」,**但一個只由禁令構成的系統,收斂終點是「乾淨的無名氏」** —— Directus、任何一個守紀律的 admin panel,長得都像這樣。作者性(authorship)不可能從禁令推導出來,它需要一個**可指名的設計主意**。

### 0.3 主意要從哪裡來(方法,非 vibe)

依 [[feedback-frontend-premium-bar]] 第一鐵則,主意必須有 rationale。合法的來源只有一個:**這個產品獨有、而競品沒有的材料**。盤點:

- Weyver 的主畫面**不是** dashboard、不是 feed、不是 canvas —— 是**單據**(docs/24 §0:「自己建、自己填」的表單記錄)。
- 使用者是台灣的會計、採購、品管、廠長 —— 他們的職業生涯建立在**紙本公文書**上:請購單、傳票、發票、檢驗報告。那個世界有自己的視覺語言:**明體標題、印章、表格框線、騎縫、存根**。
- `docs/14` 早已把「全框線欄位表」定為視覺簽名、把「長得像客戶原本的紙本單據」寫進定位 —— **但只做了框線這一項,沒有把「紙本公文書」當成完整的視覺語言去經營**。

**主意(一句話)**|**把數位單據當「正式文件」排版,把殼退成「案頭」。** 單據是紙,殼是桌面 —— 紙用文件的字體、文件的表頭、文件的印記;桌面沉默、無框、只提供光線層級。品牌感不來自裝飾,來自「**這家產品把文件當文件對待**」的整體姿態 —— 這正是 VisAWI Craftsmanship 的定義(「skillful and coherent integration of all relevant design dimensions」,docs/14 §0.3):一致地貫徹一個概念,而不是增加變化。

## 1. 五個具名手勢(每個附 rationale;mockup 內以 G1–G5 對映)

### G1|案頭與紙 —— 兩材質的明度劇場

殼(導覽軌 + 狀態列)整體**沉半階**(`s3` 家族),單據面**維持最亮**(`s1`),兩者的明度差從現行的「一階」拉開到「兩階」;單據以 luminance 浮起 + 一條 hairline,**維持零 resting 陰影**。

- **Rationale**|docs/29 S2「層級靠面」的邏輯終點:如果層級靠明度,那主角就該擁有最大的明度對比。現行殼(`s2`/`s3`)與紙(`s1`)只差半階,「紙浮在桌上」的感知不成立。**這不是加東西,是把既有規則做到位。**
- **與現行的差**|`--color-nav` 從 `s3` 深化、main 的圓角浮起保留;殼上文字對比重驗(CI 既有)。

### G2|明體文件標題 —— 台灣公文書的字體語言

**單據語言**的展示層(表單名、記錄頁大標、列印抬頭、區段標題)改用 **Noto Serif TC(思源宋體)**;**殼語言與所有內文、控件維持 Inter + Noto Sans TC 不動**;數字維持 IBM Plex Mono tabular。

- **Rationale**|台灣的正式文件 —— 公文、契約、統一發票、傳票 —— 標題慣用明體/宋體;對 Weyver 的使用者(會計、廠長),明體標題是「這是一份正式單據」的**既有信任訊號**,不是美學偏好。這是**心智模型錨定**的字體選擇(docs/24:單據長得像客戶原本的紙本),與「換個有個性的字體」(skill 泛用建議:Geist/Satoshi)本質不同 —— 後者是 vibe,前者有出處。
- **邊界(防濫用)**|只准 ≥16px 的展示層;內文、表格、控件、殼一律不得用(明體小字在低解析螢幕的可讀性差,且會滑向復古裝飾)。**Serif 只出現在「單據」上 —— 它本身就成為單據語言與殼語言的第三個區分軸**(框線之外)。
- **成本(誠實列出)**|Noto Serif TC 字重檔案大;僅載 600/700 兩字重 + `font-display: swap`,並以 next/font subset。待驗:CJK subset 後的實際 KB。

### G3|文件表頭(document header)—— 信任訊號的成形

記錄頁的頂部從「標題 + 散落的 metadata」改為**正式文件表頭**:表單名(明體)、單號(mono)、狀態印記(G4)、以及一列 **colophon**(建立人時 / 最後修改 / 版本 / 簽核鏈)—— 如同公文的發文字號與日期欄。

- **Rationale**|docs/14 §3.6 的信任訊號(時間戳/版本/稽核)現況是散在頁面各處的 12px 灰字 —— 資訊在,但**沒有被設計**。公文書把這些資訊放在固定的、正式的位置,那個「固定與正式」本身就是信任的來源。把信任訊號**組成一個可指名的元件**,同時解決「品牌感」—— 每一張單據的表頭都是品牌的出現場合(docs/29 曾裁定品牌載體=標誌用法/標題排版/列印抬頭,本手勢是其落地)。

### G4|狀態印記(status chop)—— 不可變的視覺化

單據的關鍵狀態(已過帳 / 已簽核 / 已作廢)以**印記**呈現:方形、hairline 框、明體、既有狀態色 token 三值(字/框/底),置於文件表頭右側,下附日期。**一份文件至多一枚。**

- **Rationale**|台灣商業文件以**用印**表達「此狀態已成立且不可回改」—— 與帳務不可變鐵則(AGENTS.md P0-4)是同一個語意。印記把「過帳後不刪不改」從系統行為變成**看得見的承諾**。
- **邊界(防 kitsch)**|不旋轉、不做仿舊紋理、不用篆體;就是一個方章形狀的狀態元件,吃既有 `--color-ok/wn/er/nt` 三值組。**這是狀態章(既有元件)的單據語言變體,不是新色彩系統。**

### G5|帳簿數字 —— 金額欄的簿記排版

金額欄位:IBM Plex Mono tabular(既有)+ **右對齊 + 千分位 + 合計列頂線**(單線=小計、雙線=總計 —— 簿記慣例);借貸平衡列以等寬並排呈現。

- **Rationale**|複式簿記的排版慣例(合計雙底線)是會計的母語;docs/18 的「算」是產品命門,**「算」的結果值得被當成帳簿排版,而不是普通表格 cell**。成本近零(CSS),辨識度高。
- **待裁定**|負數用紅字(台灣慣例「赤字」)或括號 `(1,234)`(英美簿記)—— 紅字與 `--color-er` 語意相撞,傾向括號,列 OQ。

## 2. 明確不做的(反手勢)

| 不做 | 為什麼 |
|---|---|
| 織紋 / 雲朵 / 線頭圖形進 chrome | docs/26 明訂隱喻「存於敘事非介面裝飾」;織的隱喻只准出現在登入頁 / 空狀態 / 對外品牌物 |
| 紙質紋理、仿舊、摺角、陰影擬物 | 「紙」只取**明度與排版**兩個性質,不取材質擬真 —— 擬物是 kitsch 的入口 |
| 漸層 / pill / resting 陰影 / 大留白 hero | 既有一票否決維持(docs/14 §0) |
| 殼上任何 serif | Serif 是單據語言的專屬記號,殼用了就稀釋 |
| 為「高級感」引入新色 | 色彩系統不動;方向的全部力量來自明度、字體、排版 |

## 4. 風險與待驗證

1. **Noto Serif TC 載入成本**|CJK serif 字檔大;需 next/font subset 實測。若 >200KB/字重則降級方案:標題僅系統明體(`"PMingLiU"`, `"Noto Serif TC"` 之 local 優先)。
2. **明體在低倍率螢幕的 rendering**|1x 螢幕小於 16px 會發虛 —— 已以「≥16px 展示層」為硬邊界,mockup 需在 1x 外接螢幕實看。
3. **「正式感」與「親和」的張力**|全明體表頭可能讓輕量表單(如內部意見調查)顯得過重 —— 待驗:是否依表單型別分級(正式單據 vs 一般表單),或一律採用以保一致性。傾向**一律採用**(VisAWI:一致 > 變化),列 OQ。
4. **G4 印記的文化負載**|對非台灣市場(若日後外銷)印記語意仍通(日韓同源),歐美市場感知未驗 —— R1 客群 100% 台灣,不阻擋。
