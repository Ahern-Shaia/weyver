## 0. Weyver 威脅模型(特有攻擊面,依風險排序)

| # | 攻擊面 | 為什麼是 Weyver 最高風險 | 主控制 |
|---|---|---|---|
| 1 | **多租戶跨租戶洩漏(BOLA/tenant-bleed)** | 一個漏洞洩漏另一家公司整本帳(OWASP web #1 + API #1)| RLS + object-level authz + 跨租戶隔離測試 |
| 2 | **動態 DDL/DML identifier 注入** | 使用者定義表/欄名 → identifier 無法參數化,最 novel 破口 | catalog 白名單 → quote_ident → per-tenant 最小權限角色 → timeout |
| 3 | **AI/LLM(prompt injection + 未驗證輸出執行)** | AI 生成 SQL/DDL/表單 + copilot 動作(docs/17)= 最大新攻擊面 | 結構化 intent → 確定性驗證 → 人核准 → audit(§4)|
| 4 | **供應鏈(fork MIT + npm deps)** | fork Baserow/Teable + OSS deps → 中毒 upstream 變你的碼 | lockfile + ignore-scripts + 掃描 + 逐檔 review fork |
| 5 | **財務資料完整性 / 竄改** | ERP 帳務,合規敏感 | 傳票不可變 + 反向沖轉 + tamper-evident audit(docs/18)|
| 6 | **3rd-party ERP / 政府 API 不可信輸入** | 鼎新/正航 對接 + 電子發票政府 API | 視為不可信,驗證 + timeout + TLS verify(API10)|

## 1. 應用安全(OWASP Top 10 + API Top 10)

### 注入 + 動態 identifier(P0 最高風險鏈)
- **[P0]** 所有**值**參數綁定(Drizzle/Knex binding),禁字串拼接。
- **[P0] 動態 identifier 安全鏈**|(1) 使用者欄名 → 經 metadata catalog **白名單解析**成物理 identifier,查無即拒;(2) 建表時 identifier 用嚴格 regex `^[a-z_][a-z0-9_]{0,62}$` + 長度鎖死,catalog 本身不可能含惡意名;(3) 驗證後的 identifier 用 `quote_ident`/Knex `??`/`%I` **加引號(第二層)**;(4) 動態 DDL/DML 跑在**只限該租戶 schema 的最小權限角色**(驗證漏了也碰不到別租戶/系統表);(5) `statement_timeout` + row limit。
- **[P1]** `knex.raw()` 無 binding 一律 code review gate;禁 shell/`exec`(必要用 `execFile` + arg array);`ORDER BY`/方向由 enum/switch 導,禁 raw。

### 存取控制 / 授權(P0 首位)
- **[P0]** server-side **deny-by-default**;每查詢綁 `tenant_id` + **object-level authz**(驗證此人能存取**這個 ID**,非只是登入)= 防 BOLA/IDOR。優先 data-access 層 / RLS 強制,任何查詢無法漏。
- **[P0]** resolve 使用者 ID 後**重驗 object 授權**;UUID 為 defense-in-depth,**非授權控制本身**。
- **[P1]** function-level authz(RBAC/Guard)蓋每 route 含 admin;禁 mass assignment(DTO whitelist,禁 spread body 進 entity → 擋走私 `isAdmin`/`tenantId`);path 正規化防 traversal。

### AuthN / JWT / 加密
- **[P0]** `verify()` 傳明確 `algorithms` 白名單,拒 `alg:none`;用非對稱 RS256/ES256(防 RS256→HS256 混淆);驗 `exp/iss/aud`;access token ≤15min + rotating refresh + server 撤銷。
- **[P0]** 密碼 **Argon2id**(≥19MiB, iter≥2)或 bcrypt(cost≥10);每 hash 唯一 salt。
- **[P0]** **TLS 1.2+ everywhere**(edge/service/DB)+ HSTS;敏感資料 at-rest **AES-256-GCM** + KMS;禁自製 crypto;token/ID 用 `crypto.randomBytes`/`randomUUID`,**禁 `Math.random()`**。
- **[P1]** cookie `HttpOnly; Secure; SameSite=Strict`;**token 禁存 localStorage**;login/MFA/reset rate-limit + 通用錯誤訊息防列舉。

### 輸入驗證 / SSRF / XSS / headers
- **[P0]** 邊界 allowlist 驗證(class-validator DTO + 全域 ValidationPipe)。
- **[P0] SSRF**|每個使用者 URL(ERP adapter/webhook/URL 欄)解析成 host/IP 驗證(非 raw URL)+ allowlist;否則擋私網段 `10/8`/`172.16/12`/`192.168/16`/`127/8` + link-local + 雲 metadata `169.254.169.254`;**禁 HTTP redirect** + egress firewall + IMDSv2。
- **[P1] XSS**|靠 React 自動 escape;避免 `dangerouslySetInnerHTML`(必要用 DOMPurify);嚴格 **CSP**(`default-src 'self'`,無 `unsafe-inline`/`unsafe-eval`)。**LLM 輸出禁未編碼當 HTML/markdown 渲染**。
- **[P1]** 檔案上傳:magic bytes 驗型別(非副檔名)+ 大小上限 + webroot 外 + 生成檔名 + `Content-Disposition: attachment` + `nosniff`。
- **[P1]** Helmet(Fastify)+ CORS 明確 allowlist(禁 `*` + credentials)。

### 設定 / DoS / 日誌 / API
- **[P0]** 禁回傳 stack trace/DB 錯誤(全域 exception filter 回通用訊息 + correlationId);**per-tenant 最小權限 DB 角色**(無 SUPERUSER/CREATEROLE;migration 角色分離)。
- **[P0]** 動態查詢 `statement_timeout` + per-tenant 資源上限(防自傷 DoS);全域 throttler + body size 限制 + **強制分頁上限**。
- **[P0]** 日誌**禁記 secret/token/密碼/PII**(logger 端 redact);**[P1]** append-only tamper-evident audit(財務 who/what/before/after,與 app-writable 分離);記安全事件(authn/authz deny/admin/租戶變更)。
- **[P1] API Top 10**|BOLA/BOPLA 物件 + 屬性級授權;高價值流程(過帳/付款核准)防自動化濫用(step-up/anomaly);**3rd-party ERP 回應視為不可信**(驗證+timeout+TLS verify,API10)。

## 2. 供應鏈安全

- **[P0]** commit lockfile + CI 用 `pnpm i --frozen-lockfile`(禁 `^`/`~` 靜默拉惡意新版);**全域 `ignore-scripts=true`** + 只 allowlist 可信 builder(擋 `postinstall` 攻擊);每 PR + 每日跑 **OSV-Scanner/Snyk + `npm audit`**,high/critical fail CI。
- **[P0]** **fork 的 MIT(Baserow/Teable)逐檔 review + 每次 upstream sync re-diff**(中毒 commit 變你的碼)。
- **[P1]** build pipeline 產 **SBOM**(CycloneDX/SPDX);**7 天版本 cooldown**(擋 npm campaign);target **SLSA L2+**(OIDC publish、無長效 npm token、隔離 runner)。
- **[P2]** 最小化 deps + `npq` 篩 typosquat。

## 3. Secrets / 基礎設施 / 容器

- **[P0]** **零 secret 進碼/git/committed .env**(即使私 repo);全存 **Infisical**,runtime 注入;每憑證最小權限;**secret 從 log/錯誤/LLM prompt redact**(key 貼進 prompt = 洩漏給模型商)。
- **[P0]** 容器 **non-root USER + read-only rootfs + drop caps**(CIS Docker);**distroless/minimal base + Trivy/Grype 掃描** critical fail CI;**TLS everywhere + Postgres 絕不對公網開**(Coolify 綁內部 Docker network);**自動備份 + PITR + 已測還原演練**(未測=沒備份)。
- **[P1]** Postgres CIS 硬化(`scram-sha-256`/`ssl=on`/嚴格 `pg_hba`);網路分段(public proxy zone vs private app/DB);VPS 硬化(SSH key only/firewall default-deny/fail2ban/auto patch);secret 排程輪替 + KMS envelope 加密金鑰分離。
- **[P2]** base image pin digest(非 `:latest`)。

## 4. ⭐ AI / LLM 安全(最大新攻擊面 —— OWASP LLM Top 10 2025)

> **載重不變量**|**模型提議「結構化 intent」→ 你的確定性程式碼驗證 / 授權 / 執行 → 有權限的人核准每個狀態變更。** 模型永遠是不可信輸入,不是可信程式碼。(此 pattern 亦即 docs/20 GoRules ZEN:AI 生成決策表 → 驗證 → 確定性執行。)

- **[P0] 絕不執行未驗證的 LLM 輸出**(LLM02 Improper Output Handling)|「AI 生成 SQL」的正確做法:
  1. 強制模型輸出**結構化 intent JSON**(tables/columns/filters),**非 raw SQL 字串**。
  2. **你自己**用 allowlist query builder 把 intent 編譯成 SQL,**只用參數化**,禁把模型文字拼進 query。
  3. NL→SQL 走**唯讀、tenant-scoped DB 角色** + statement timeout + row limit;拒 intent schema 不允許的 DDL/DML。
  4. AI 生成表單/DDL:對嚴格 schema 驗證 + 走 migration path + 人審;**模型絕不直接碰 DB**。
- **[P0] 每個狀態變更的 copilot 動作都 human-in-the-loop**(LLM08 Excessive Agency)|copilot 提議,有權限的人確認才執行。
- **[P0] copilot 跑在操作者本人的權限 + 租戶 scope**,每 tool 最小授權,每動作 audit(who/what/when/tenant)—— agent 不得超過使用者手動能做的。
- **[P0] 防間接 prompt injection**(LLM01)|客戶表單資料 / 記錄 / 文件餵給模型 = 不可信;明確分隔外部內容與指令;retrieved 資料不得升權或觸發 tool call(需上述人核准 gate)。
- **[P1] 防敏感資料洩漏給模型**(LLM06)|prompt 前過濾 / 最小化 PII 與財務資料;提供 **regional / self-host 推論選項**(資料落地需求);合約確認不用於訓練。
- **[P1] LLM 呼叫 per-user/tenant rate + token cap + timeout + 成本預算**(LLM04 DoS + 失控成本);spend 異常告警。
- **[P1]** system prompt 約束角色 + 輸出 schema 驗證 + 每版 release 前 red-team injection/jailbreak。
- **[AVOID]** LLM 輸出禁未編碼渲染 HTML(XSS);**授權絕不由模型決定**(由你的程式碼)。

## 5. 多租戶安全(詳 docs/21)

- **[P0]** tenant filter 在 **data-access 層(RLS + ORM auto-scope)**,非 middleware(結構上不可能漏);每接受 ID 的請求驗 object ownership(RLS 被 raw query 繞過時的第二層)。
- **[P0]** **CI 自動跨租戶隔離測試**|A 建資料 → 切 B context → 斷言看不見;涵蓋 API / raw query / 背景工作 / cache key / 檔案路徑(全是常見繞過向量)。
- **[P1]** 背景工作 / cache / 檔案儲存帶租戶 context(丟失=靜默洩漏);per-tenant secret/金鑰隔離;防租戶列舉(非序 ID + 統一錯誤 + rate limit);per-tenant 資源配額防 noisy neighbor。

## 6. ⭐ 四軸反思(跨 22 份規劃的系統性檢視)

> 每軸三欄|**現有優勢**(已規劃)· **反思補洞**(⚠️ 新識別)· **落地優先**。可執行的工程鐵則已整合進 AGENTS.md「可靠 / 穩定 / 高效能」section。

### 6.1 更安全

| 現有優勢 | ⚠️ 反思補洞 | 落地 |
|---|---|---|
| 三大風險面已控(動態 identifier / 跨租戶 / AI-LLM);統一載重 invariant(提議→驗證→人核准→audit,§4 = docs/20 ZEN = docs/18 過帳);defense-in-depth;傳票不可變 = tamper-evidence | **模組間零信任**|即使單體,跨模組呼叫不隱式信任租戶 context,一律重新從 CLS 取 + RLS 兜底 | P0 |
| | **敏感欄 field-level 加密**|銀行帳號 / 薪資超越 at-rest,獨立金鑰(per-tenant)| P1 |
| | **audit 當防禦資產**|異常存取偵測(大量匯出 / 異常時段);**mass export = 外洩向量** → rate-limit + 告警 | P1 |
| | **客戶自建表單的安全預設**|客戶建表單不得無意造成注入 / 曝露 PII —— 引擎強制欄位級權限 + 驗證由客戶配置但引擎兜底 | P1 |
| | **break-glass admin + 租戶下線安全刪除 / 匯出**(churn 時)| P2 |

### 6.2 更可靠

| 現有優勢 | ⚠️ 反思補洞 | 落地 |
|---|---|---|
| DBOS durable execution(結轉 / 對帳 / 電子發票 crash-resume);過帳 / 沖帳單一 transaction;PITR + 已測還原;Edge store-and-forward | **冪等性(idempotency)**|所有 mutation / webhook / AI 動作 / **電子發票政府 API 提交** 帶 idempotency key,重試不重複過帳 / 不重複建單 / 不重複開票 | **P0** |
| | **Outbox pattern**|跨模組副作用(採購→財會拋轉)即使單體亦走 outbox,保證最終送達(crash 不丟事件)| P1 |
| | **不變量對帳 job**|定期斷言:試算表恆平衡、庫存數量 = 異動帳、AR/AP = GL 明細;不符即告警(資料完整性守門)| P1 |
| | **背景工作 retry + backoff + dead-letter queue**;**RPO/RTO 目標明定** | P1 |

### 6.3 更穩定

| 現有優勢 | ⚠️ 反思補洞 | 落地 |
|---|---|---|
| modular monolith 邊界 + dependency-cruiser CI;兩層解耦(docs/19)先出穩定 ERP;noisy-neighbor 隔離(rate + statement_timeout) | **優雅降級**|AI/LLM 掛 → 核心 ERP 照常(AI 非關鍵路徑);搜尋掛 → fallback SQL;MES 採集洪峰 → ERP UI 不受影響(獨立 process,docs/11 §2.2)| **P0** |
| | **circuit breaker + timeout + bulkhead**|所有外部呼叫(ERP adapter / LLM / 政府電子發票 / SCADA)| **P0** |
| | **load shedding / backpressure**|過載時捨低優先(AI / 報表)保核心交易 | P1 |

### 6.5 反思的元結論

- **三個 P0 新洞** —— **冪等性、優雅降級 + circuit breaker、N+1 防護** —— 是現有 22 份規劃的真實補洞,已整合進 AGENTS.md 強制鐵則,不留在反思當孤立筆記。
- **一致性 dividend**|安全 §4 的「提議→驗證→人核准→audit」invariant、可靠的 outbox/idempotency、穩定的 degradation、效能的 background worker —— 四軸互相強化,不是各自為政:例如「重計算走背景 worker」同時是效能(不擋請求)+ 穩定(隔離)+ 可靠(DBOS durable)。**同一架構決策服務多軸,是好設計的訊號。**
