## 3. 🔴 六個承重發現

### 3.1 表格的垂直框線是分水嶺

**Qualio / Directus / Metabase —— 三個看起來最像產品的,表格都只有水平線。**
**Ragic —— 這個庫裡最像後台的 —— 是唯一畫垂直線的。**

⚠️ Weyver 現況與 A/B/C/D **四版全部有垂直線**(每格 `border`)。

### 3.2 兩個最像產品的都用「深殼淺紙」

Qualio(深藍全高側欄)、Directus(深藍窄圖示軌)—— **兩者的內容區都是白的**。
淺色側欄的 Ragic 最像後台。Weyver 現況與 A/B/C/D 全是淺色側欄。

⚠️ **深色「殼」與深色「內容」是兩件事**。已刪的 `docs/37` 把「全深底」列為 D4 並指出它
與閱讀研究相衝 —— 那條反對**只針對內容深底**,不適用於深殼淺紙;
而深殼淺紙正是已刪 `docs/36` D1「墨檯上一張發光的紙」的形狀。
**同一結論從兩個獨立來源出現**(自架實走截圖 + 已作廢的方向稿),值得當回事。

### 3.3 主色不進資料區

六個產品**沒有一個**在表格儲存格上底色。主色只出現在三處:**側欄選取態 · 連結 · 主要按鈕**。

⚠️ 這一條打臉我的 D 版 —— 我把 fx 欄整格上綠底。它有功能理由(「哪些數字是算出來的」),
但**零競品支持**。要保留就得承認是刻意偏離,不能說是慣例。

### 3.4 密度靠「多行儲存格」不靠「多欄位」

Qualio 每一列是**兩行**,列高約 72px。它一屏塞的資訊不比我們少,但讀起來鬆。
我們是**一列一行、11 欄橫向擠** —— 這正是決策方說的「資訊堆得太滿」。

### 3.5 主要按鈕不一定是實心

Qualio 的 Export 是**外框線**;實心只留給真正的主要動作。
我們現在每個工具列按鈕都長一樣,沒有主次。

### 3.6 大頁面標題本身不是問題

Qualio 有 ~30px 的頁面大標題(「Audit trail」),而它看起來像產品。
**所以 C 版的失敗不是「標題放大」本身** —— 是「標題放大 **+** 四層水平帶 **+**
壓縮列高 **+** 拿掉表頭底色」這個組合。§5.2 要照這個修正來讀。

| # | 問題 |
|---|---|
| 🔴 **同屏五組導覽** | ①最左圖示欄(4 個**無標籤**圖示)②頂欄左(我的表單/範本/匯入 Excel/+新增)③頂欄右(設計·填單·網格·資料)④表單清單欄 ⑤欄位型別欄。**頂欄左右兩半性質完全不同**:左=建新表的三條路,右=看當前表的四種模式 |
| 🔴 **圖示欄零文字標籤** | 144 張表單的工作區,主導覽是 4 個無標籤圖示。同時是 a11y 問題 |
| 🔴 **2D 畫布在欄位多時退化成一維長條** | 實測 45 欄位:每列一個欄位、右側全空。因為新欄位的預設落點是「往下接一列、佔半寬」(`form-geometry.ts` 的 `effectiveLayout` 逐字)。**換視覺方向不會改善它** |
| 儲存位置不唯一 | 畫布右上有「儲存版面」,頂欄另有一組操作 |

- 只走了五個畫面;看板 / 行事曆 / 樞紐 / 圖表 / 設定其餘分頁**沒走**

- **沒有使用者研究**。以上是對照自家文件推出的張力,是**假說不是結論**

## 5. A/B/C/D 四版試作 —— 含兩次失敗的假設

mockup:`docs/mockups/workspace-abc.html`(A/B/C 並列)· `workspace-d.html`
截圖:`ia-audit-2026-08-06/ab-a.png` · `ab-b.png` · `abc-c.png` · `d-ver.png`

| 版 | 是什麼 | 結果 |
|---|---|---|
| **A** | `workspace-ragic.html` 的視覺尺度(7–10px 圓角 / pill / resting 陰影 / fx 彩色底) | 決策方原始偏好 |
| **B** | 同結構,改用 `tokens.css` v4 **實際值**(3/4/6px / 帶框方形章 / 無陰影) | 與 A **看起來是同一個產品** |
| **C** | B + 放大標題與留白 | 🔴 **「完全錯誤,更像後台」** |
| **D** | 照決策方圈的三條觀察做(色彩承載資訊 / 真 Lucide / 網格為主角) | 待評 |
| **E** | 照 §3 六個產品的實測提取做 | 待評 |

### 5.1 A/B 的量測:裝飾不是主因

| | A | B |
|---|---|---|
| 網格選取列對比 | 1.138:1 | 1.135:1 —— **幾乎一樣** |
| 側欄選取項對比 | 1.098:1 | **1.021:1** —— B 太弱,是缺陷 |
| 主色按鈕白字 | 5.00:1 | **7.59:1** —— B 反而好 |

被辯論的四項裝飾,已刪的 `docs/37 §1` 自己量過四站的結論逐字:
**「按鈕圓角無共識(4/6/10/pill),屬方向自由度」**(Stripe 4px · Linear 6px · Attio 10px · Mercury pill)。
既然頂級產品各走各的,圓角就不可能是「像不像後台」的原因。

### 5.2 🔴 失敗一:「後台感 = 沒有層級」

C 把層級實作成「標題放大 + 留白拉開」,而**那個組合就是 admin panel 的招牌版型**
(頁面大標 → 留白 → 分頁列 → 工具列 → 密表格,四層水平帶各用橫線隔開;
Django / Rails / WordPress admin 全是這個形狀)。

另外兩個自造的傷:**把表頭底色拿掉只留一條線**(那是沒上樣式的 HTML table)、
**列高壓到 34px**(密度是 ERP 訊號不是產品訊號)。

⚠️ §3.6 修正了這條:Qualio 有大頁面標題卻像產品。**錯的是組合,不是標題。**

### 5.3 🔴 失敗二:「後台感 = 網頁感」

修正後我猜「A 像產品是因為圓角+陰影讓它讀成應用程式視窗」。
問決策方時,**那一項沒有被圈**。

### 5.4 ✅ 決策方實際圈的三條(D 的依據)

1. **色彩太素 / 太灰**
2. **元件粗糙 / 像預設控件**
3. **資訊堆得太滿、沒有重點**

第②條是字面事實不是感覺:**A/B/C 的圖示是 `▦` 這個 Unicode 字元,checkbox 是瀏覽器預設的
`<input>`** —— 而 memory `feedback_frontend_premium_bar` 早就逐字點名「真 Lucide」。三版都沒做。
D 已改為 inline SVG + 自繪 checkbox + 有 hover/focus 態的控件。

### 5.5 E 版:照 §3 的六條提取做

`docs/mockups/workspace-e.html`,截圖 `e-ver.png`。**依據是六個產品的橫向對照,不是我的假設。**

| §3 的發現 | E 的作法 |
|---|---|
| 3.1 只有水平線 | 表格**零** `border-left/right`;子表同 |
| 3.2 深殼淺紙 | 深藍全高側欄(圖示+文字+分組,選取=實心色塊)+ 白內容區。**頂欄只在內容區之上,不橫跨側欄**(Qualio 的分工) |
| 3.3 主色不進資料區 | 儲存格**一律不上底色**,含 fx —— fx 改靠字色 + mono(W3 暫依競品) |
| 3.4 多行儲存格 | **11 欄 → 8 欄**:單號+批號 / 供應商+聯絡人 / 品項+倉別 / 數量+單價 / 交期+相對天數 / 簽核+狀態 |
| 3.5 按鈕分主次 | 匯出 ghost · 設計表單 外框 · 建立記錄 實心 |
| 3.6 標題可有份量但避開 C 的組合 | 標題 19px 與主要動作**同一列**;下面直接接檢視+工具(兩層,不是四層);列高不壓 |

🔴 **色彩存在感改由深色側欄承擔** —— 那正是 Qualio / Directus 在「主色不進資料區」前提下
仍有品牌感的作法。側欄色由 `--base-brand` 推導,白牌不受影響。

⚠️ **E 自己的兩個弱點,先誠實記下**:
1. **「含稅」那一行是湊出來的**|金額欄底下沒有天然的第二行,我為了套用兩行模式硬加了一個
   幾乎沒有資訊量的字。§3.4 的手法**不是每一欄都適用**,硬套就會產生填充物。
2. **可見列數從 8 掉到 6**|兩行儲存格換來的可讀性,代價是一屏看得到的筆數變少。
   Qualio 付得起(稽核軌是慢速瀏覽),採購單列表**可能付不起**(要掃很多筆)。
   這一條要看真實使用情境才判得準。
