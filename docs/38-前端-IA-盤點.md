## 3. 🔴 量出來的:共識、以及四個「量了但沒用」的指標

色彩與密度**不是用眼睛判的** —— 用 `sharp` 對全部 225 張逐張抽像素統計
(量化到 24 階去抗鋸齒雜訊,分中性 / 彩色 / 深色三軸 + HSL 色相)。

### 3.1 ✅ 共識一:內容底色近純白

**十家的第一名中性色全部落在 `#fcfcfc` 附近**,佔比 38–85%:

| 家 | 第一中性 | 佔比 |
|---|---|---|
| Metabase | `#fcfcfc` | 84.6% |
| ERPNext | `#fcfcfc` | 80.1% |
| NocoDB | `#fcfcfc` | 77.2% |
| Odoo | `#fcfcfc` | 76.8% |
| Qualio | `#fcfcfc` | 61.1% |
| ragic-detail | `#fcfcfc` | 57.5% |
| Ragic | `#fcfcfc` | 53.1% |
| Directus | `#fcfcfc` | 50.7% |
| Dynamics 365 | `#fcfcfc` | 43.0% |
| isoTracker | `#fcfcfc` | 38.0% |

**十家、零例外。** 這是本次唯一 100% 的共識。

### 3.2 ✅ 共識二:主色相落在 H210–250

Directus H249–252(紫)· Dynamics H216–228 · Metabase H210–240 · NocoDB H220–226 ·
Qualio H225–240 · Ragic H210/H240 —— **六家同帶**。
例外:Odoo 是唯一多色相(H136 綠 / H41 琥珀 / H355 紅 / H30 橙)· ERPNext H336 粉 · isoTracker H30–36 橙。

🔴 Weyver 現行 `--base-brand:#22568a` 算出來是 **H210**,**在共識帶的下緣**。
**色相選擇沒有問題**,「太素」不是色相的錯。

### 3.3 ✅ 共識三:可編輯網格**要**格線,唯讀清單才只有水平線

線條密度(相鄰像素亮度落差 >6% 的比例):

| 產品 | 密度 | 表格性質 |
|---|---|---|
| NocoDB | **9.58%** | **可編輯網格** |
| Ragic 列表 | **7.91%** | **可編輯網格** |
| Qualio | 6.79% | 唯讀清單 |
| Metabase | 5.35% | 唯讀清單 |
| Directus | 4.62% | 唯讀清單 |

🔴 **這推翻了本文 v2 的一條結論。** v2 寫「垂直框線是分水嶺,像產品的都只有水平線」——
那是**過度概化**:只有水平線的三家全是**唯讀清單**,而兩個**可編輯網格**都有格線。
**格線是「這一格可以點進去改」的訊號**,不是後台的證據。
Weyver 的列表頁是可編輯的(Glide grid),**應該有格線**。

### 3.4 🔴 四個量了但**不能**分辨「像產品 vs 像後台」的指標

| 指標 | 範圍 | 為什麼沒用 |
|---|---|---|
| **彩色像素比** | 3.1% – 24.4% | Directus **3.1%** 最低卻像產品;isoTracker **22.7%** 高卻最像後台 |
| **深色像素比** | 0.0% – 14.7% | Metabase **0%** 像產品;Qualio **14.7%** 也像產品;isoTracker **7.3%** 像後台 |
| **線條密度** | 3.46% – 9.58% | **Qualio 6.79%(像產品) vs isoTracker 6.40%(像後台)—— 幾乎一樣** |
| **主色相** | 六家同帶 | 同一個色帶,觀感天差地遠 |

**結論:沒有任何單一量化參數能分開兩者。**
所以「加顏色」「加深色」「減框線」都不是答案 —— 這也解釋了為什麼
`tokens.css` v4 檔頭記的那三次(加顏色 → 色彩模型化 → 做工藝)都沒有解決。

### 3.5 其他可直接引用的觀察

- **主色只出現在三處**:側欄選取態 · 連結 · 主要按鈕。**六家沒有一個在資料儲存格上底色**
- **主要按鈕不一定實心**:Qualio 的 Export 是外框線,實心只給真正的主要動作
- **欄位型別以圖示 + 型別色標示**(NocoDB,Airtable 血統)—— 型別是 metadata,色彩在此承載資訊
- **Ragic 的單據頁用實心深藍分段條** + 灰標籤格 / 白值格 + 必填紅星 + `?` 說明。
  那是它**最清楚**的部分,值得借
- **大頁面標題本身不是問題**:Qualio 有 ~30px 大標卻像產品
- **共識元素**:⌘K 全域搜尋 · 底部狀態列(筆數 + 分頁)· 欄標題可點排序

### 5.1 🔴 從失敗學到的三條(唯一值得留的部分)

1. **「標題放大 + 留白拉開」= admin panel 的招牌版型**。
   頁面大標 → 留白 → 分頁列 → 工具列 → 密表格,四層水平帶各用橫線隔開 ——
   Django / Rails / WordPress admin 全是這形狀。
   ⚠️ 但 §3.5 顯示 Qualio 有 30px 大標卻像產品,**所以錯的是組合不是標題**。
2. **表頭底色不能拿掉**。只留一條線的表頭,就是**沒上樣式的 HTML table**。
3. **圖示不能用 Unicode 字元湊**。`▦` 這種東西是「像預設控件」的直接來源;
   `feedback_frontend_premium_bar` 早就逐字點名「真 Lucide」。
