## 3. Ragic 完整功能地圖

> 基於 15 張官方 doc 截圖 + 官網 features + doc-kb + 使用者反饋 校準。分 11 大類。

### 3.1 平台 & 帳號管理(基礎)

- **多帳號切換**|同一登入,跨組織 / 帳號切換(ragic-04 截圖確認)
- **管理使用者 + 群組**|Admin 建帳號、加入群組
- **外部使用者**|給客戶 / 供應商填單,不佔 seat
- **應用商店(App Store)**|預裝模板庫(CRM / 進銷存 / HR / 專案 等 100+ 產業範本)
- **付款管理**|訂閱升級 / 使用者增減
- **備份**|自助備份下載
- **資源回收桶**|刪除記錄暫存,可還原
- **個人設定**|使用者偏好、介面語言(多語切換)
- **主題設定**|表單主題色 / 品牌客製

### 3.2 表單設計(Ragic 招牌)

- **Excel-like 網格編輯器**|直接在表格上設計欄位(vs 表單 designer 拖拉)
- **30+ 欄位型別**(ragic-10 截圖確認)|
  - 基本|自由輸入 / 數值 / 日期 / 循環日期 / 百分比
  - 選單|從選單選擇 / 從選單多選 / 打勾選項
  - 關聯|從其它表單選擇(Link & Load)
  - 檔案|檔案上傳 / 圖片上傳
  - 使用者|選擇使用者 / 選擇群組
  - 進階|自動產生(格式化)/ 簽名 / 文字編輯器 / 條碼 / 文字遮罩
- **自動編號 pattern**(ragic-14 截圖確認)|`{0,number,00000}` / `PO-{1,date,yyyyMMdd}-{0,number,000}` 等
- **子表(Subtable / Line items)**|訂單品項、發票明細等一對多結構
- **表單分段(Section)**|同一列可放多個 tab,視覺減壓
- **表單設定**(ragic-01 截圖確認)|存取權限、提醒、簽核流程設定、動作按鈕、條件式格式、主題設定、App 排版顯示順序、快速範本
- **用既有 Excel 建立表單**(ragic-07/08 截圖確認)|**Ragic 差異化 onboarding 神器**|上傳 Excel 自動生成表單 schema
- **快速範本**|從範本庫 clone 表單
- **表單版本 / schema migration**|欄位變更後歷史記錄相容

### 3.3 資料檢視

- **列表視圖**(list view)|預設篩選 / 排序 / 分組
- **Kanban 看板視圖**|依欄位值分組成 board
- **Calendar 行事曆視圖**|依日期欄位視覺化
- **Map 地圖視圖**|依地址欄位放在地圖上
- **樞紐分析(Pivot Table)**|多維度交叉分析
- **單筆表單視圖**|傳統表單 CRUD
- **儲存篩選條件**(saved views)|每人可存自訂視圖(ragic-13 截圖確認)
- **個人化列表欄位選擇**|每人自訂看哪些欄位(ragic-14 截圖確認)
- **左側 quick-filter sidebar**|依欄位值快速篩選 group
- **標星號(star / favorite)**|快速訪問常用資料

### 3.4 公式與自動化

- **公式引擎**|200+ 函式(Excel-like)、跨欄位、跨表計算
- **觸發器(Triggers)**|新增 / 修改 / 刪除 / 條件變化觸發

## 5b. Ragic 實務上已被拿來取代 ERP —— 需求驗證與「那道牆」

> **這是 Weyver 整個立論的市場驗證。** 需求端不是猜的,是**觀察到的客戶行為**:客戶已經主動在 Ragic 上重建 ERP 內容,只是撞到一道明確的牆。Weyver 補的正是那道牆。

### 5b.1 客戶已經做到的(Ragic 自由度高,~80% ERP 內容可重建)

Ragic 的**連結與載入 + 子表格 + 公式 + 工作流簽核 + 三層權限 + API**,讓中小廠把大量 ERP 內容原封不動搬進來,用得不錯:

| 已被重建的 ERP 內容 | 為什麼 Ragic 做得到 |
|---|---|
| 進銷存(採購單 / 銷貨單 / 訂單 / 報價) | header + line items 是 Ragic 甜蜜區(子表格)|
| 主檔(客戶 / 供應商 / 商品) | 表單 + Link&Load 關聯 |
| 簡易庫存(進出、數量加減) | 公式 + 關聯累加 |
| 簡易生產(工單追蹤、BOM 存放、領料記錄) | 表單 + 子表 |
| 品質 / ISO(檢驗表、不合格記錄、文件表單) | 表單 + 工作流 |
| HR 基礎(員工 / 請假 / 打卡) | 表單 + 簽核 |
| 單據流程(各式簽核) | 工作流編排 |

對很多中小廠,這「**幾乎就取代 ERP 了**」—— 這是真的,也是 pilot 客戶主動來找開發者做這套系統的原因。

### 5b.2 剩下的 20% —— 「算」不是「填」,而它的答案是寫程式

> 🔴 **2026-08-02 逐條查證更正**|本表原寫「Ragic **做不到**」,經 Ragic 官方文件一手查證為**過度斷言**。
> 官方逐字:「所有表單都可以觸發 Ragic 的 **伺服器端 JavaScript 工作流程引擎** 來執行複雜的業務邏輯,
> 如**計算成本和發布庫存餘額**。基本上,任何 **Ragic 現有功能無法覆蓋的複雜業務邏輯**都可以透過伺服器端程式來實現。」
> (`doc/29/javascript-workflow-engine.html`)
> **正確的說法是「能做,但要寫程式」** —— 而那正是它承諾「不用寫程式」卻沒兌現的地方。
> ⚠️ 對外一律**正面表述**(Weyver 讓你不用寫程式就做得到),不講對手做不到 —— 說「做不到」會被懂 Ragic 的客戶當場反駁。

Ragic 是**表單資料庫**,不是**計算引擎**。重建到約 80% 後,剩下這些**無內建、需自寫伺服器端程式**:

| 項目 | 現況(2026-08-02 查證) | 依據 |
|---|---|---|
| **正式會計 / 總帳 GL** | ✅ **確實無**|總帳 / 借貸 / 傳票 / 分錄 / 損益表 / 資產負債 全庫 **0** 命中;設計手冊 10 章無會計章 | 全庫關鍵字 |
| **成本會計** | ⚠️ **無內建,官方指引寫 JS**|標準 / 分批 / 分步結轉、差異分析皆無現成功能 | `doc/29` 逐字列「計算成本」為 JS workflow 適用情境 |
| **MRP** | ⚠️ **無內建**|BOM / 需求展開 全庫 **0**;BOM 需自建表單,展開需自寫 JS | 全庫關鍵字 |
| **庫存估值** | ⚠️ **無內建**|加權平均 / 先進先出 **0**;數量加減可用公式,成本結轉需自寫 JS | `doc/29` 逐字列「發布庫存餘額」 |
| **稅務 / 電子發票合規** | ✅ **確實無**|加值中心 / 財政部 **0**;「電子發票」僅出現在 Ragic **向客戶收款**開票,非產品能力 | 全庫關鍵字 |
| ~~**高頻交易 + 嚴格稽核**~~ | ❌ **原斷言錯誤,已刪**|Ragic 修改紀錄比原文暗示的完整:「修改紀錄會先顯示最新的 **250 筆**」「可**下載修改紀錄**或**篩選歷史紀錄**」+ **逐欄歷史記錄**。若要保留須改為「**稽核 trail 的不可變性**:紀錄完整但可被有權限者刪改,無過帳鎖定與不可逆沖轉語意」 | `doc-user/8`、`doc/72`、`doc/81` |

### 5b.3 這道牆完美對應 Weyver 的兩層架構

牆的位置,1:1 對應 `docs/15 表單引擎技術設計` 的**兩層資料模型**:

- **Tier 2(使用者自建表單)= Ragic 已擅長、客戶已在做的那 80%**
- **Tier 1(系統實體真實表)+ 計算層 = 那道牆,Ragic 過不去的 20%**

**Weyver = Ragic 範式(彈性)+ 計算層(補牆)+ MES + ISO**。需求端已被客戶行為驗證,缺口端(計算層)清楚可定義。

### 5b.4 一句話 pitch

> **「你已經在拿表單平台取代 ERP 了,只差會計、成本、MRP —— 而那一段目前得寫程式。Weyver 讓那一段也不用寫程式,真正 100% 取代 ERP,還加上 MES + ISO —— 全部在同一個範式裡。」**

⚠️ **措辭紀律**|不點名、不說「對手做不到」。同樣的事實用正面表述,不可反駁,且與品牌 sober 語氣一致(見 AGENTS.md 第一約束)。

### 6.1 ERP 深度不足

- ✅ **沒有 GL / 總帳 合規會計**|總帳/借貸/傳票/分錄 全庫 0 命中
- ✅ **沒有台灣電子發票 API**|加值中心/財政部 0;「電子發票」僅為 Ragic 自身收款開票
- ⚠️ **BOM / 工單 / MRP 無內建**|原寫「只能自建 workaround」語氣過重 —— 官方明示伺服器端 JS 為 escape hatch。正確:「無內建;需自建表單 + 自寫伺服器端 JS」
- ✅ **沒有勞健保 合規薪資**|勞健保 / 投保 全庫 0
- ❌ **「沒有多幣別 匯兌損益 合規邏輯」半錯**|**有多幣別機制**:`doc/27` 逐字「**匯率** 此欄位在新增或編輯資料時會即時從 **Open Exchange Rates** 抓取匯率」「**指定匯率日期參照欄位**」;`doc/125` 有每日批次更新匯率。**缺的是匯兌損益入帳**(未實現/已實現匯差、期末重評價),「匯兌」全庫 0
- Weyver J-R 補足這些(**且維持不用寫程式** —— 見 AGENTS.md 第一約束)

### 6.2 無原生 OT 協定(原「SCADA / MES 現場整合完全無」❌ 錯誤)

- ❌ **原句「Ragic 純 SaaS」錯誤**|設計手冊**第 10 章「私有主機版說明(含 QNAP / Synology)」**,`doc/113/on-premises-installation.html` 實際存在
- ✅ **無原生 OT 協定為真**|OPC / Modbus / MQTT / PLC / 感測 / 機台 全庫 0
- ⚠️ 但有雙向 HTTP API 與 workflow「寄送 HTTP 請求」,設備資料**可由客戶自建中介程式推入** —— 即「要寫程式」而非「完全無」
- **Weyver T 模組的真實差異**|Edge Gateway 的 **store-and-forward / 斷線續傳 / 毫秒級採集**,以及**不必自建中介程式**

### 6.3 無對帳領域邏輯與預建 ERP 連接器(原「多 ERP 整合概念無」❌ 錯誤)

- ❌ **原句錯誤**|`doc/98` 逐字:「要將 Ragic 與外部系統整合的話,有以下幾種**不用另外寫程式**的方法以及 **2 種需要客製化程式**的做法」
  —— 定期網址匯入 / 發佈到網路 / Zapier·Make·IFTTT / **SQL 資料庫同步**(MySQL·PostgreSQL·SQL Server,可每日自動)/ Looker Studio / n8n / SurveyCake / **MCP**
- ✅ **真正缺的**|預建 ERP 連接器與**跨系統對帳語意**。鼎新 / SAP / Odoo / QuickBooks 全庫 0 命中;唯一會計串接範例是透過 Zapier 接 Xero
- **Weyver Q 模組的真實差異**|在**對帳領域邏輯**,不在「能不能連」

### 6.4 預測型分析弱(原「AI/ML / AI 幾乎無」❌ 錯誤)

- ❌ **原句錯誤,且是全庫最嚴重的一條**|Ragic 有設計手冊**第 8 章 Ragic AI 小幫手**:AI 建資料庫(需求→自動生成一系列表單 + 關係圖)、NL 查詢、**AI Agent(6 觸發 × 11 動作,含 `CREATE_RECORD`/`MODIFY_RECORD`)**、MCP(唯讀繼承權限)、AI 公式助手、單據抽取(拍發票自動填單)、私有主機本地模型 + BYO key
- ✅ **弱的是預測型分析**|預測 / 機器學習 / 迴歸 全庫 0
- ✅ **且 AI 不介入計算層**|AI 只輔助設計與查詢
- 詳見 docs/17 v2 §0(該處錯誤已 cascade 修正)

### 6.5 大團隊授權成本高(⚠️ 推論需節制)

- Enterprise 牌價 US$55/user/月(最低 10 人)× 100 user = US$5500/月 = **NT$16.5 萬/月**
- ⚠️ **原推論過度**|另有**無限使用者方案**(企業版 US$1399/月含 10 併發)與**大量使用者折扣**、教育/非營利優惠。
  故「200 人一年 NT$400 萬」是**未折牌價上限,非實付** —— 對外引用會被反駁
- ❓ **官方定價完整級距未查證**(定價頁不在本地鏡像),US$55 數字來自 `doc-kb/154`

### 6.6 可寫 code,但脫離自助範式(原「不能直接寫 code」❌ 錯誤)

- ❌ **原句錯誤**|設計手冊**第 9 章「系統客製化 - 給程式設計師」**:9.1 RESTful HTTP API / 9.2 **JavaScript 工作引擎** / 9.3 Workflow 產生器;
  支援 Pre/Post/動作按鈕/簽核/General/Daily workflow;企業版另可自行撰寫客製化 jsp
- ✅ **真正的限制**|無版控、無測試框架、無 package 生態、無型別安全,且**一旦落到 JS 就脫離「不用寫程式」的範式**
- 🔴 **這正是 Weyver 的向上位置**|凡是 Ragic 要你寫 code 的地方,就是我們該做成 no-code 的地方(AGENTS.md 第一約束)

### 6.7 行動 App 深度中等

- ✅ **離線為真**|`doc-app/5` 逐字:「**不支援在離線狀態下新增或編輯資料**」;App 內亦無法設計表單 / 跑 JS workflow / 批次匯入匯出
- ❌ **「掃碼 workflow 較弱」錯誤**|`doc/27` 有 **動作條碼** 欄位型別:「掃描條碼後可以執行…**執行動作按鈕**…例如:掃描條碼後簽到、掃描條碼後新增一筆繳費紀錄」
- **Weyver T 模組的真實差異**|**離線可新增/編輯 + 斷線續傳**(現場斷網不停擺),不是「補掃碼」
