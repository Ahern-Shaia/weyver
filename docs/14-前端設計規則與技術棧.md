# Weyver 前端設計規則與技術棧

> **文件性質**|前端開發之單一真實來源(Single Source of Truth)。**開發前定案,開發中一律遵循**。
> **視覺基準**|對齊 Dynamics 365 / Ramp / Sigma 級企業 SaaS —— 精準、克制、資料導向、可信賴。
> **配套**|設計系統視覺稿 `docs/mockups/design-system.html`(色彩 / 字型 / 元件 / Do&Don't)+ 首頁基準 `docs/mockups/homepage-v6.html` + 表單引擎 `docs/mockups/form-engine.html`。
> **版本**|2026-07-17 v1(v6 企業級方向定案後固化)

---

## 0. 定位一句話

**Weyver 是企業級多租戶 SaaS 平台**(Ragic 表單 + ERP + MES + ISO 一站式)。前端要看起來像**嚴肅、有力、可信賴的企業級資料產品**,不是消費級 App,也不是 generic 後台管理系統。

## 2. 設計 Token(CSS variables — 定案)

> 完整互動展示見 `docs/mockups/design-system.html`。以下為權威數值,Tailwind config 與 CSS 皆由此生成。

### 2.1 品牌 · 深海青

```css
--teal-900:#073B47; --teal-800:#0C5F73; /* brand */ --teal-700:#0E7490;
--teal-600:#12879F; --teal-400:#3AA9BE; --teal-200:#BEDDE4; --teal-100:#DBEBEF; --teal-50:#EAF3F5;
--color-brand:#0C5F73; --color-brand-hover:#0E7490; --color-brand-tint:#EAF3F5;
```

**為什麼深海青**|台灣 ERP 競品(鼎新 / 正航 / SAP B1)清一色藍或灰藍 → 此色差異化;兼具精密儀器感 + 「織雲」的雲 / 水意象。

### 2.2 中性 · Ink / Surface

```css
--ink:#181E26; --ink-2:#586069; --ink-3:#868E98; --ink-4:#AEB6BF;
--bg:#F4F6F8; --card:#FFFFFF; --head:#FCFCFD;
--border:#E2E7EB; --border-2:#EDF0F3; --border-3:#F1F4F6;
```

### 2.3 語意 · 狀態(各含 base / tint / dark 三階)

```css
--green:#0E9E5B; --green-t:#E6F6EE; --green-d:#0A7D48;   /* 完成 / 合格 / 運行 */
--amber:#C8760C; --amber-t:#FBF2E3; --amber-d:#9A5A05;   /* 警示 / 近期到期 */
--red:#D23B32;   --red-t:#FCEEED;   --red-d:#B02B22;     /* 異常 / 超限 */
--blue:#2E6FE0;  --blue-t:#EBF1FD;  --blue-d:#2159C0;    /* 採購 / 系統提示 */
--violet:#6D45C9;--violet-t:#F0EBFA;--violet-d:#5836A8;  /* ISO / 文件 */
```

### 2.4 圓角 · 陰影 · 間距 · 動效

```css
/* 圓角(企業級偏緊)*/
--r-sm:6px;  /* 按鈕 / 輸入 / 控制 */   --r:8px;  /* 卡片 / 面板 */   --r-lg:10px; /* modal */   --pill:9999px;

/* 陰影(深度靠細邊框 + 極輕陰影,非軟陰影)*/
--sh:0 1px 2px rgba(20,26,36,.05);                                       /* 靜態 */
--sh-2:0 2px 8px -2px rgba(20,26,36,.10),0 1px 2px rgba(20,26,36,.05);   /* hover / 浮層 */

/* 間距(4 / 8 節奏)*/  4 · 8 · 12 · 16 · 24 · 32 · 48

/* 動效(150–200ms,ease-out 進 / ease-in 出)*/
--t:130ms cubic-bezier(.2,0,.15,1);
```

### 2.5 字型系統 · IBM Plex(定案,經視覺評估)

**選定 IBM Plex 超家族**(見 `docs/mockups/typography-eval.html` 三套並排視覺評估)。

```css
--font-sans:'IBM Plex Sans','IBM Plex Sans TC','Noto Sans TC','PingFang TC',system-ui,sans-serif;
--font-mono:'IBM Plex Mono','JetBrains Mono',monospace;
```

**為什麼 IBM Plex 而非 Inter**|
1. **企業級 DNA** —— IBM 委託設計的**企業識別字體**,為企業軟體而生;工程 / 精密性格呼應製造業 ERP / MES。
2. **一套設計語言貫穿 Latin + 繁中 + Mono**|Plex Sans + **Plex Sans TC** + Plex Mono 同源超家族 —— 系統化一致性正是讀起來企業級的關鍵。Inter / Geist 都得外配 Noto,是拼裝。
3. **Plex Mono 的 slab 襯線**|批號 `BN-0715-A` / GL 代碼 / 金額 tabular 對齊時,辨識度與技術感明顯強於 JetBrains Mono。
4. **OSS(OFL)**|符合 [[oss-only-stack]]。
5. **明確不是 Inter**|脫離「AI 生成預設」訊號(2026-07-17 user 指出 Inter = AI 感,要求實際視覺評估)。

**備選**|Geist(現代技術感,偏科技新創氣質,繁中需外配)。

## 3. 設計規則(鐵則)

### 3.1 四大原則

1. **整合 · 一站式**|Ragic 表單 + ERP + MES + ISO 同一 shell、同一 token;切模組像切分頁,跨模組資料流動可見。
2. **精準 · 克制**|中性灰白為主,深海青只點在重點(active / 連結 / 主行動 / 關鍵數字);細邊框 + 極輕陰影。
3. **資料導向**|KPI / 圖表 / 資料表為主體;數字 tabular-nums;密集但井然有序。
4. **可信賴 · 企業級**|資料更新時間戳、同步狀態、篩選控制常駐;嚴肅有力,不消費風。

### 3.2 App Shell(定案結構)

```
┌─────────────────────────────────────────────┐
│ 頂欄 52px:品牌 + 全域搜尋(⌘K)+ 建立 + 帳號  │
├────────┬────────────────────────────────────┤
│ 左導航  │ sub-header:標題 + 資料更新時間戳     │
│ 216px  │           + 時段分段 + 篩選 / 匯出    │
│ 工作區  ├────────────────────────────────────┤
│ + 模組  │ KPI 列 → 模組一站式 → 資料表 + 圖表   │
│ + 已整合│ 內容區 max-width 1280               │
│  系統   │                                    │
└────────┴────────────────────────────────────┘
```

### 3.3 元件慣例

- **按鈕**|每畫面只有 1 個 Primary;Secondary / Ghost 次要;Danger 與主行動分隔。
- **狀態**|一律 `dot + 文字`,不只靠顏色(WCAG 1.4.1);pill 形淡底同色深字。
- **資料表**|hairline 列分隔(**非斑馬紋**);hover 抬升;數字欄右對齊 mono;checkbox 多選 → bulk action bar。
- **表單引擎 Grid**|欄位型別標示(`#`自動編號 / `$`金額 / `fx`公式 / 關聯 / 選項 / 日期 / 成員);公式欄淡青底;點 row → 右側明細(子表 + Link&Load)。
- **Focus**|深海青 3px tint ring;鍵盤全可達。
- **圖示**|Lucide outline,stroke 一致,**無 emoji**。

### 3.4 多租戶

- 每廠家 = 一個固定租戶 = 一個工作區,**不放切換工作區 UI**(見 [[project-weft]];集團多廠區為進階例外)。
- 頂欄 / 導航顯示固定租戶識別(如「鮮勇工作區」)。

### 3.5 a11y / 響應式

- 對比 AA 4.5:1;內文 ≥ 14px;focus ring 明顯;鍵盤可達。
- 響應式斷點 375 / 768 / 1024 / 1440;寬資料表可橫向捲動(刻意例外)。
- 尊重 `prefers-reduced-motion`。

## 4. Do & Don't(6 版迭代教訓)

| ✅ Do — 企業級 | ❌ Don't — 消費 / 後台陷阱 |
|---|---|
| 頂欄 + 左導航 + 內容專業 chrome | in-app 漸層 hero banner(行銷頁手法)|
| 資料更新時間戳 / 同步狀態 / 篩選信任訊號 | 織雲等品牌隱喻外顯為畫面裝飾 |
| 細邊框 + 極輕陰影建立深度 | 暖色漸層卡、彩色 icon 塊(消費風)|
| 中性灰白 + 深海青精準點綴 | 大圓角 + 軟陰影堆疊(廉價感)|
| KPI / 圖表 / 資料表資料導向,tabular-nums | 整片灰色資料表無層次(generic 後台)|
| 狀態 = 顏色 + dot + 文字 | 斑馬紋列(ERP legacy)|
| Lucide outline,一致筆畫,無 emoji | 切換工作區 UI(單一租戶無此情境)|

> **迭代紀錄**|v1 高管 KPI 看板(功能不對)→ v2/v3 角色工作台(太像單廠內部工具)→ v4 App Hub(方向對但陽春)→ v5 暖色品牌漸層(誤走消費級)→ **v6 企業級 chrome + 資料導向(定案)**。關鍵教訓:「死板」指視覺工藝不夠企業級,不是缺溫度;修法是專業 chrome + 系統化精準,不是加暖色。
