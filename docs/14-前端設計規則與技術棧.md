### 0.4 v6「token 架構」對照 Metabase(2026-08-01 裁定)

> **來源**|`docs/28-Metabase-設計分析.md` —— 數值與規則取自 Metabase 原始碼直讀,非二手。
> **性質**|本次裁定**大部分是確認既有規則**,只有三條是新規;另有一條是**更正 docs/28 v1.0 自己寫錯的**。

**(a) 三條新規(採用)**

| 規則 | 為什麼 |
|---|---|
| **色彩兩層制**|`--base-*`(唯一可調來源,元件不得直接用)→ 語意 token(元件唯一可用層) | Metabase 逐字:「Base colors … should never change and **never be used outside this file**」。我方目前是直接把 hex 寫在語意 token 上,新增一個主題要動 61 個值 |
| **主色階由 base 以 `color-mix` 推導** | 白牌客戶換一個變數,深淺 / hover / focus / 淡底全部跟著對。白牌是 docs/04 v2.6 的既定需求;現行做法是每個主題手寫三個值。⚠️ **改完必須跑 `contrast.test.ts`**,不過就退回手調並記錄該色相為例外 |
| **`--icon-*` 明文對齊文字階** | Metabase 逐字註解 `// Matches text-primary`。可消滅「圖示比旁邊的字深一階、但說不出理由」這一整類問題 |

**(b) 🔴 「禁硬編 hex」由文件規定升級為 CI(已落地)**

本節開頭的「禁硬編 hex」原本**沒有任何檢查**。補上 `color-literal.test.ts` 的當下就照出三個**已在線上**的不一致:

- `theme-switcher` 色塊寫死 `#1E4E79`,而 tokens.css 已是 `#22568a` → **點下去的顏色與切出來的主題不同**(設計系統頁、帳號選單同病)
- `grid-tone` 抄了一份 12 組狀態色,檔頭自白「異動需同步」
- 簽名筆寫死 `#0C5F73`(深海青)→ 不管選哪個主題都畫深海青

三者已改為讀同一組 CSS 變數。**規則沒有檢查就會漏,字階是前車之鑑(漏到 16 種)。**

**(c) 明確**不**採用(對照後維持原判)**

| Metabase | 我方 | 理由 |
|---|---|---|
| 圓角 md = 8px | 維持 6px 上限 | §0.1 v3 已把柔角鬆綁到 4–6px 為**有據**上限;8px 屬較柔的 SaaS 語彙 |
| 三階陰影(含 resting) | 維持**只有 overlay** | §2.4 既有裁定;其陰影雖極淡(alpha 0.05–0.08)仍不構成推翻理由 |
| 字階 11/12/14/17/21 | 維持整數六階 | 兩者都是刻意收斂,差異不構成改的理由;我方有 CI |
| 儀表板為主的 IA | **明確不搬** | 與 docs/24「主畫面非 KPI 儀表板」直接衝突 |

**(d) ⚠️ 更正 docs/28 v1.0 的一條錯誤:12.5px 不是「外部佐證」**

docs/28 v1.0 見 Metabase 的 `tableCell: 12.5px` 與我方根字級相同,寫成「兩個產品獨立收斂」。**該結論不成立** ——
**§2.5(2026-07-31)明文否決 12.5px**(逐字:「於三大系統皆無對應且會產生 sub-pixel rounding」),全庫也沒有任何元件用它。
真相是:Metabase 的表格字級**恰好落在我方已否決的值上**,這是**分歧不是佐證**。

🔴 **`globals.css` 的根字級 `12.5px` 是殘留**(其註解仍引用已被取代的 v2 依據)→ **列為待清理**,不是待補佐證。
可借的只有一點:Metabase 把 **pivot 表再降一階**(12px),與我方 12px 地板相容,F-2 可比照。

**(e) 待另立 OQ**|動作型別專屬色(Metabase 給 filter / summarize 各一個核心色)。
概念可採,但我方的高頻動作語彙是**設計 / 填單 / 簽核**,顏色不照抄;需先定語彙再裁定。

### 0.3 v5「工藝感可量測」+ 刪除無據主張(2026-07-31 裁定)

> **來源**|`docs/modules/R1/frontend-uplift.md` 研究 D / E(OQ-FUX-3 / 14 全採)。

**(a) 工藝感有量表、有門檻、有窗口 —— 不再靠主觀爭論**

- **VisAWI**(Moshagen & Thielsch 2010)四面向之一即 **Craftsmanship**,逐字定義「the skillful and coherent integration of all relevant design dimensions」;其為**對設計品質最敏感之面向**(同內容美/醜兩版 **d=1.60**,Diversity 僅 0.49)。
- **VisAWI-S 短版 4 題**(與全版 r=.91、α=.81)可直接前後測;官方門檻 **>4.5**(162 網站常模 M=4.51)。⚠️ 常模來自消費型網站,**B2B 內部工具無常模** → 以**自身前後測差異**為判準。
- 🔴 **投資窗口 = 首次接觸**|50ms 即可形成印象;但 **2 週開始衰減**(Sonderegger 2012)、**7 週歸零**(Sauer & Sonderegger 2022, N=110,逐字「no effect… including perceived usability」)。
  → **優先序**:登入 → 首頁 → 第一次建表 → 第一次填單,**優先於深層設定頁**。
  → **不得承諾**:對已使用數月之日常使用者,工藝帶來持續的效率或滿意度收益。
- **施力方向 = 一致性與概念完整**(其題目即:`professionally designed` / `designed with care` / `lacks a concept (r)`),**不是增加變化** —— 與字階收斂 / 對比一致 / 間距節奏重合。
- 🔴 **不得以「提升效率」為由推動視覺工藝**:效果量小(統合分析 **g = 0.12**)且**方向無共識**(2023 年 n=281 研究完成時間 d = −0.06, p = 0.60)。正當理由為**信任感與感知專業度**(感知面效果穩健,r>0.9)。

**(b) 🔴 應從規範與討論中刪除的六條(無證據或方向相反)**

| 主張 | 實際 |
|---|---|
| 字型家族數上限(如 ≤2) | **查無任何同儕審查實驗**測字體家族**數量**之效果 |
| 減少色彩數量 | 🔴 **方向相反**:低圖形介面主色較多反而評分較高,**企業表單正屬此類**。⚠️ **不得外推**為 chrome 使用裝飾色之授權(該研究測美感評分非資訊編碼)|
| 留白越多越好 | white space **僅在高圖形頁**降低美感,其餘不顯著 |
| 對稱性 | 受性別調節;計算指標於模型中被剔除 |
| 複雜度倒 U(「適度複雜最好」)| 兩篇獨立研究否證,實為**線性負向** → 正確做法是**避開高複雜度**,再往下壓收益趨零 |
| 好看 → 長期更好用 | 7 週實驗零效果 |

**(c) 降複雜度的可操作指標**|單畫面**視覺群組數 / text group 數 / image area 數**(Reinecke 2013 最佳單一預測子 r=.50)。**高複雜度會吃掉「照慣例做」的全部紅利**(原型性效果 d 由 1.96 崩至 .24)→ **先降複雜度,再談版型創新**。可自動計算並進 CI 者:**grid quality**、figure-ground contrast、visual clutter(Miniukovich 2015,八指標解釋美感 49% 變異)。

### 0.2 v4「類別編碼用色」解禁(2026-07-28 裁定)

> **裁定**|用戶明示「推翻 docs/14 §0.1 也沒關係,我要的是完整的解決方案」(選項顏色設定 UI 之 OQ-OC-1)。**解禁範圍嚴格限於「配色」一項**,漸層 / pill / resting 陰影 / 大留白 / hero / 裝飾動效 **維持一票否決**。

**為什麼這一項可以鬆(rationale 不用 vibe)**

原禁令針對的是**裝飾性用色** —— 為了好看而上色,是消費級 SaaS 的語彙。但選項顏色不是裝飾,是**類別編碼(categorical encoding)**:讓使用者在密集列表中一眼分辨「北區 / 中區 / 南區」。這與圖表用 categorical color 同性質,在嚴謹資料工具中有正當性(Excel 條件式格式、Bloomberg 終端的分類色皆然)。判準因此不是「有沒有顏色」,而是**顏色有沒有在傳遞資訊**。

**受控條件(色彩仍不得自由發揮)**

1. **兩類色分離**|**狀態色** `ok/warn/error/neutral` 承載語意(§3.7 之狀態層級不變);**類別色** `c1–c8` 不帶語意,且**刻意避開綠 / 琥珀 / 紅**三色相以免與狀態混淆。
2. **受控色盤,非自由選色**|只開放 token 內的 12 個 tone;不提供任意 hex / 色輪。元件端以白名單查表映射,查無退 `neutral`。
3. **視覺語言不變**|仍是**帶框方形章**(`radius-xs` 3px)、字/框/底三值、**文字恆在**。禁 pill、禁純色塊、禁只靠顏色傳意。
4. **去飽和 + 一致明度**|字 ~L40% / 框 ~L82% / 底 ~L95%,避免糖果色;整體仍讀作資料工具而非消費級應用。
5. **可及性**|文字恆在 → 色盲與黑白列印下資訊不失(此為「顏色只能是輔助編碼」的具體落實)。

**未鬆綁的推論**|本裁定**不**授權在 chrome(導覽 / 面板 / 按鈕)上使用類別色,也**不**授權整列著色(記錄層級著色為獨立議題,見 option-colors OQ-OC-3)。

### 0.1 v3「精緻資料工具」有據鬆綁(2026-07-20 裁定)

> **背景**|v2.1 純 austere(方角 2–3px / 全禁陰影)實作出來讀成「未上樣式的線框」。校正原則仍是 docs/11 §7.1 第一鐵則「**每個決策有 rationale,不用 vibe**」——**寫得出產品理由的才鬆,寫不出的維持禁**。toy-like 的真解 = 把嚴謹語言做出**工藝**(間距節奏、字階、對齊、真 Lucide icon、信任訊號),**非**加 Airtable 的裝飾。方向近 Bloomberg 終端高密度精品,非消費級 SaaS。

| 項目 | v2.1 | **v3 鬆綁到** | rationale(非 vibe)| 仍禁 |
|---|---|---|---|---|
| 圓角 | 2–3px | 容器/控件 **4–6px**(md=6 上限)| 純 2–3px 高密度下角落像沒畫完的線框;4–6px = 刻意描繪 | **pill / 全圓徽章**、>8px |
| 陰影 | 全禁 | **僅 overlay**(下拉/popover/modal/選單)極淡陰影(`--shadow-overlay`)| overlay 需與下層分層,hairline 分不出「浮於上」= **功能性 z 訊號** | resting 卡片/表格**仍禁陰影**(框線深度)|
| 漸層 | 禁 | **維持禁** | 無產品理由 | 品牌塊也平色 |
| 徽章/狀態 | 帶框方角章 | 維持帶框方角章(`StatusChip` = shadcn Badge outline);**+ 狀態層級**(見下)| pill 是消費裝飾;帶框章才是結構訊號 | pill;筆數/篩選也帶框非 pill;**裝飾圓點**(字已區分狀態,點=冗餘) |
| 密度 | 12.5px 緊 | **維持密度優先**;表格列高 ~34–38px;**4px 間距節奏** | 掃讀要密度;toy-like 靠節奏+字階非留白 | 46px 舒適大留白式 |
| 色彩 | 冷中性三主題+語意色 | **色只編碼語意**(狀態 / 型別族)| 色=訊號 | **裝飾性配色**(如彩色實體頭像)|
| Icon | Lucide 功能性 | 維持;**全面用真 Lucide 取代佔位字元** | §1.2 早允許;功能性辨識 | emoji / 裝飾 |
| 信任訊號 | 必備 | **強制**:時間戳到秒+人 / 版本 / 稽核 / 借貸平衡 / 狀態列 | 企業級「不像玩具」的本體語言 | — |

**token 對應**:`--radius-*` = 3/4/6/8;`--shadow-overlay`(僅 overlay);resting 一律 border。

> ⚠️ **2026-07-31 證據強度標注(必讀)**|上表之總體方向(「toy-like 的真解是把嚴謹語言做出工藝」)經查證**無外部權威依據** —— **Linear / Superhuman / Height / Sigma 皆無公開設計系統**,網路流傳者均為第三方逆向;業界亦**查無**把「專業工具 vs 玩具」拆成可操作清單的權威文件。**故本表為本專案之假設,不得以「業界如此」引用。**
> **但下列各條另有獨立佐證**:
> - **全框線(禁斑馬紋)**|A List Apart 實驗(n=2,276 有效 session):8 題中僅 3 題準確率顯著提升、速度幾無顯著;偏好調查(n>1,200)單色隔列 31% 最有幫助 / 4% 最不喜歡,**純框線版 20% / 4%** —— 兩者被討厭比例相同。**本立場站得住。**
> - **框線極淡**|見 §2.4「框線對比」之 1.4.11 判準與 Carbon 佐證。
> - **密度**|Cloudscape 密度建於 4px 單位;Carbon 列高階梯 24/32/40/48/64。
> - **信任訊號**|見 §3.6 之證據標注。

**狀態層級(§0.1 資訊設計,非外觀 uplift)**|狀態非全等重:**要行動**者(待審 warn / 退回 error)留語意色;**已了結 / settled**(已核准 / 已收貨 / 完成)用 `neutral` 退到背景,**不用 ok 綠**——讓注意力導向該處理的,而非一片綠與待辦爭注意力(Linear/Height 範式)。極密次要表可再退為純文字+語意色(無框)。狀態靠**字 + 框 + 色**三者,**不加裝飾圓點**(字已完全區分、也已色盲友善,點對辨識零貢獻 = vibe)。

| overlay 進場 / 行內展開 | `moderate-01` | **150ms** | `productive-entrance (0,0,0.38,0.9)` |

跨系統唯一共識:**進場減速、離場加速、離場短於進場、生產力情境用較短一檔**。「300ms 最自然」等說法查無出處。

**禁**(每條附依據):
- **列表/表格逐項交錯進場(stagger)**|Chevalier, Dragicevic & Franconeri, **IEEE TVCG 2014** —— 交錯宣稱能減少遮擋,但**過去無任何實證支持**,即使在最有利情境效果仍極微;且**延長最後一列可見時間**,對整天掃資料者為純成本。
- **動畫幾何屬性**(`width`/`height`/`top`/`left`/`margin`)|觸發 layout。位移類一律走 `transform`。web.dev 明載**僅 `transform` 與 `opacity` 可由 compositor 獨力處理、跳過 layout 與 paint**(正確表述**不是**「GPU 比較快」)。
- **parallax / 彈跳 / 裝飾性 motion**|無產品理由。
- **任何 shimmer 持續 >5s 且與其他內容並列**|**違反 WCAG 2.2.2 Level A**。

**`prefers-reduced-motion`**|守衛已存在於 `packages/ui/src/styles/tokens.css`,採「全部歸零」式。日後若引入位移/縮放類動效,改採 WebKit 立場「**換掉而非全關**」(位移降級為 opacity 淡入;純 opacity 維持)。

資料變更以**時間戳更新**表達,不以動畫。

### 3.15-bis 載入與版面穩定性

- **CLS ≤ 0.1 · INP ≤ 200ms**(75 百分位,官方閾值)。
- **載入指示**|**<400ms 不顯示任何指示**;400ms–10s 保留舊內容 + 表頭細進度條(不阻斷、不位移);>10s 用 percent-done + Cancel。延遲 400ms 才顯示、顯示後最短維持 500ms(防閃爍)。
  - 依據:NN/g「<2s 不需指示」;Fiori 規定延遲顯示 + 最短 500ms;Salesforce 取 >300ms。**400ms 為本專案取值**(兩者無共識)。
- **禁整頁替換式載入**(`if (isLoading) return <載入中…>`)—— 造成版面塌陷與位移。改用 `keepPreviousData`。
- **不採骨架屏於局部重查詢 / 篩選 / 換頁**|Viget(n=136)三組對照中 skeleton 組**全面最差**;高密度表格若列高與真實列不符會**自製 CLS**。「骨架屏快 30–50%」查無原始研究。
- 🔴 **輪詢刷新 / 背景 job 插入列 / 推播不吃 CLS 互動豁免**(豁免僅離散輸入後 500ms,且 scroll/drag 不算)→ 必須預留空間或走 `transform`。
- 圖片標 `width`/`height` 或 `aspect-ratio`;字型 `font-display: optional` + `size-adjust`。

## 4. Do & Don't(v2)

| ✅ Do — 嚴謹企業級 | ❌ Don't — 普通 SaaS |
|---|---|
| 全框線欄位表、柔角 4–6px、框線深度(§0.1 v3)| 大圓角 >8px、resting 軟陰影、飄浮卡片 |
| 扁平主色分段條、active tab 實底 | 淡色 hero 分段、漸層 |
| 帶框方形狀態章 | pill 徽章 |
| 帶框工具列 + 單一 primary + 記錄導航 | ghost 按鈕群、多 primary |
| 時間戳到秒、版本、稽核入口、狀態列 | 無 system info 的「乾淨」畫面 |
| 科目代碼、借貸平衡斷言、列號、統編 | 只給結果不給依據 |
| 整數字階(地板 12 / 表格 13 / 內文 14)、Mono tabular 數字 | 非整數字級、8–11.5px 微字、大留白行銷排版 |
| 功能藍 underline 連結 | 隱形連結 |
| 表單記錄為主畫面(docs/24)| KPI 儀表板當首頁 |
| Lucide 功能性圖示、無 emoji | 彩色 icon 塊、emoji |
| 左側導覽含文字標籤(≤7 主目的地)| >7 個純圖示 rail(Material 明載上限 7)|
| 保留舊資料 + 延遲 400ms 細進度條 | 整頁替換成「載入中…」(版面塌陷)|
| placeholder ≥4.5:1 | 又縮小又調淡(≤13px 配 disabled 級色)|
| Carbon productive token(70 / 110 / 150ms)| 入場動畫 / **stagger**(IEEE TVCG 2014 否證)/ 裝飾動效 |
| 一個 Ragic 工作區、能力織入 | 每系統一個模組 tab |

> **迭代紀錄**|v1 經 6 版首頁迭代定「軟企業 SaaS」(深海青/圓角/陰影)→ 2026-07-19 經 docs/24 心智模型校準(form-first、Ragic 範式)+ 用戶指正「太像普通 SaaS,無 Ragic/ERP/MES/ISO 嚴謹感」→ **v2 嚴謹企業級定案**(全框線/方角/扁平分段條/密度/信任訊號)。教訓:企業級的信任感來自**嚴謹的結構訊號**(框線、代碼、時間戳、平衡斷言),不是品牌色與留白。
