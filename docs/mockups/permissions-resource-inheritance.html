權限管理 — 資源軸繼承(對照現況)

現況以「每張表單 × 動作」逐項列舉,deny-by-default:新建表單在配置前對所有非管理員角色隱形,維護量隨表單數線性膨脹 —— 與「自己建自己填」的自助定位衝突。提案在分類 / 資料夾設一次授權、表單繼承,逐表僅作覆寫;敏感表以旗標保留嚴格 deny。授權單位由 O(表單) 收斂為 O(分類)。角色軸繼承(角色樹)已 SHIPPED,此為在資源軸補上同一套繼承。

現況 form_permissions 逐表列舉(已 SHIPPED) 提案 form_def 加 category · 分類授權表 · 解析序:表單覆寫 → 分類 → 預設 profile
建立者自動擁有owner

誰建表誰即全權,自建表免等 admin 授權即可用(Ragic 範式)。解掉「自己建了卻看不到」的第一道摩擦。

分類繼承(最大槓桿)O(分類)

權限設在分類(約 10 個),表單預設繼承。維護量由 O(表單×角色) 收斂為 O(分類×角色),有界。逐表僅在刻意偏離時覆寫。

敏感旗標 + 預設flag

一般表給合理 baseline;僅標記敏感(金額 / GL / HR)才走嚴格 deny。維護負擔只落在真正該審的少數表。
