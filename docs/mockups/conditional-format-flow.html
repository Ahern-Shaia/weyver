條件式格式 — UI Flow

模組 R1·UP-3b（form-designer-2d P1 殘留）。採 Ragic 範式:表單級設定、欄位值與標題著色、後者覆蓋、記錄頁與列表頁各自獨立。
顏色沿用 option-colors 的 12 tone 受控色盤(非自由選色,docs/14 §0.2)。
此頁為設計稿。以下所有標註與說明皆在產品 chrome 之外;產品畫面內不出現任何開發階段字樣。
這份稿要你確認的四件事
  • 入口位置 — 放在設計器「版面設計」工具列(與 文字/圖片/分段/動作/列印 同層)。
  • 覆蓋序的表達 — Ragic 是「排越後面越優先」,與多數人對規則清單的直覺相反。稿中以常駐提示 + 即時預覽處理,你看夠不夠清楚。
  • 色盤限制 — 只能從 12 個 tone 選,不能自由選色。Ragic 可自由選色,遷移時客戶的自訂色會被映射到最接近的 tone。
  • 兩面分開設定 — 記錄頁與列表頁各一組規則,提供「複製到另一面」。

＝本模組刻意不做的事

條件式「行為」不納入(顯示 / 隱藏 / 唯讀 / 必填)

  • 條件式隱藏不是安全邊界。 呈現層藏起來 ≠ 沒權限拿到;誤用會讓人以為敏感欄已受保護。欄位級保護一律走權限設定。
  • 條件式必填若只在前端就是裝飾 — 要真的有效必須改後端記錄寫入驗證。
  • 納入會把一個「純呈現、零安全面」的模組,變成有安全與驗證面的模組 → 另立模組處理。

其他

  • 整列著色(Airtable record coloring)— 記錄層級,獨立議題。
  • 欄位間交叉比較 — 與 Ragic 同,以公式欄替代。
  • 圖示 / 粗體 / 資料條 — Ragic 未見,先只做色。
  • 自由選色 — 受控 12 色。遷移時客戶自訂色映射到最接近的 tone(非色色相符)。
