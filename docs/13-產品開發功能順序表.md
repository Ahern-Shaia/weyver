## 0. 排序原則(先讀,避免爭論)

### 0.1 三大原則

0. **★ 一切皆表單(架構主張,2026-07-17)**|**表單引擎是 substrate,不是模組之一**|ERP/MES/ISO 之單據 / 主檔 / 品檢 / 文件皆為引擎上的表單 app。故**表單引擎(動態 schema + 子表 + 公式 + 關聯 + 工作流 + 權限)是最先做、最不能妥協的平台投資**;之後 ERP/MES/ISO 大量復用它。深層計算(GL / MRP / 成本 / 估值)為引擎之上的計算層,隨各模組補上。
1. **Dependency-first**|上游 blocking module 先做|表單引擎 substrate blocks 90% 其他 module
2. **可上線交付**|**Phase 1(完整 Ragic 平台)**之產出必須「一家 pilot 客戶可用」,不做半殘 feature
3. **收費驅動 backlog**|Phase 1 land 既有客戶愈早,現金流愈早進來 → 之後 Phase 2/3 資源就位

### 0.2 Solo dev vs Team 之差別

| 面向 | Solo(16-18 hr/day)| Team(8 人)|
|---|---|---|
| 並行度 | 1 stream(頂多 2 交錯) | 8 stream(依模組拆) |
| Bandwidth 產能 | effective 務實 ~8 / 加速 ~12 人月-equiv / 月(計導入+維運稀釋;純 coding 峰值遠高非瓶頸;Vernova 校準 docs/07 §1.4。舊 ~2 為校準前過度保守值)| ~10-12 人月-equiv / 月(含 overhead) |
| Deep work 領域 | 一次 focus 1-2 個模組 | 可同時 8 模組 |
| Bottleneck | 開發者本人 | Communication + integration |
| **本排序表用途** | 逐項 sequential 執行 | 拆多條 parallel track(見 § 8)|

### 0.3 何時偏離順序表

- **Pilot 客戶硬 deadline**|17 家導入 pipeline 之上線 deadline 硬 conflict → 優先導入,Weyver R&D 暫停
- **Blocking bug**|上游 module 出現 architectural 問題 → 回頭 refactor 而非往下推
- **需求變更**|pilot 客戶 must-have feature 之前未預期 → 插隊,更新 backlog
